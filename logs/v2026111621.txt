## 关键日志
### S1 — 根因与设计
- 目标: 为 agent 系列增加按 run ID 恢复 CLI 原生会话的能力。
- 根因: 既有 `--resume RUN_ID` 无条件进入 headless drive，恢复后自动发送“继续”；不符合用户期望的原生 TUI resume。
- 兼容决策: 单独 `--resume RUN_ID` 进入 TUI；与 `--once`、`-time/--time`、`--max-turns`、`--max-runtime`、`--stop-file` 等驱动选项同用时保持既有 headless 行为，自动恢复链协议不变。
- 旧 run 处理: manifest 缺少 session/thread 时，通过 `tools/agent-session-state.py` 按 run_id、cwd、created_at 只读反查；唯一命中后补写 manifest。Command Code 旧 TUI run 还可用启动时写入的 run 名兜底。

### S2 — 实现
- 共享 Unix runtime 增加 session/thread 反查与补写函数。
- Claude: `claude --resume <session>` 进入原生 TUI。
- OpenCode: `--session <session>` 进入 V1/V2 原生 TUI。
- Codex: `codex resume <thread>` 进入原生 TUI；本地 app-server 路径同步支持。
- Command Code: `command-code --resume <session|run-name>` 进入原生 TUI。
- Windows runtime 同步解析语义、TUI 参数和 session 反查。
- 恢复 TUI 时日志改为追加，避免覆盖原 `agent.log`。
- 非 TTY 输出不再启动后台 `tail -F` 实时监视器，避免 CI/命令替换被后台管道阻塞。
- 修复 Windows 中三处既有的 `@resumeBase` 数组表达式语法错误。

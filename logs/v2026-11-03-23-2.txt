## Agent 全文报告
--- report begin ---
问题不是 BYOK 配置不对，而是 Command Code 的账号认证门与模型通路是解耦的两件事：`cm go` 只把 `opencode-go` 写进 `providers.json` 并加 `--skip-onboarding`，但 CLI 交互式启动会无条件执行 `requireAuth → ensureAuthenticated`，只认 `COMMAND_CODE_API_KEY` 环境变量或 `~/.commandcode/auth.json` 的 `apiKey`。`--local-only` 不豁免这道门（已实测：无 key 报 Not authenticated，假 key 报 Authentication failed）。

根因在启动器的分支不对称：只有 `gt` 分支把 `COMMANDCODE_GOAT_API_KEY` 映射为 `COMMAND_CODE_API_KEY`，`go`/`pay` 分支只注入各自的 BYOK 推理密钥，账号凭据缺兜底，所以另一台机器在无 auth.json 时必停在登录页。

已修复（Linux + Windows 两端同步）：
- 新增账号凭据探测 `_commandcode_account_key_present` / `Test-CommandCodeAccountKeyPresent`，顺序与 CLI 一致：环境变量 > auth.json.apiKey；
- BYOK 通路缺账号凭据时，若有 `COMMANDCODE_GOAT_API_KEY` 则自动作账号认证并打印 note（模型请求仍走 opencode-go）；
- 完全无凭据时提前告警"CLI 会停在登录门"，不再静默卡住。

验证：agent.test.sh 全量 88 项 PASS / 0 FAIL（含新增 3 个用例）；Windows 静态契约 PASS；隔离 HOME 端到端复现确认——有 goat key 直接进 TUI，无凭据给出明确告警。

另一台机器只需 `git pull` 后 `source ~/env-key.sh`（其中已有 COMMANDCODE_GOAT_API_KEY）再 `cm go`，即可不再弹登录页。若想用独立账号而非 goat key，跑一次 `command-code login` 落盘 auth.json 也可。

`env-key.sh` 未被触碰，仍不在任何 Git 仓库内。

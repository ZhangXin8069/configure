**测试口径**
- 标准任务：官方 HumanEval，固定提交 `b9453e8f1865df0a0057a1383767caa400acfbcf`，数据集 SHA256 `b796127e635a67f93fb35c04f4cb03cf06f38c8072ee7cee8833d7bee06979ef`。
- 样本：按固定 seed 的 SHA256 顺序，从 164 题抽取 16 题，做 16 个题内配对。
- 两臂固定 `go / deepseek-v4.1-flash / max`、同一 launcher、工作区结构、300 秒上限和隐藏测试。
- `native`：`agent-dispatch` 最小原生提示，不注入本库完整 prompt/skills。
- `library`：本库完整 prompt、全局/工作区技能清单与自动技能编排。
- 每个任务使用全新 Git 工作区和独立 agent thread；隐藏测试不暴露给代理。

**核心结果**

| 指标 | 原生最小提示 | 本库完整配置 | 本库/原生 |
|---|---:|---:|---:|
| HumanEval pass@1 | 16/16 = 100% | 16/16 = 100% | 0 个百分点 |
| Wilson 95% 区间 | 80.64%-100% | 80.64%-100% | 相同 |
| 平均 total tokens/题 | 38,513 | 385,666 | 10.01x |

**如何解读**
- 正确率：本样本没有观察到差异；16 题全对也使 McNemar 检验 p=1，样本不足以排除很小的差异。就这批短程算法题而言，完整配置没有带来正确率增益。
- token：本库配置的平均 token 是原生的 10.37 倍（逐题比值均值，中位数 9.67 倍）；聚合总量为 6,170,652 对 616,208，即 10.01 倍。缓存输入计入 total；按未缓存输入看仍为 9.44 倍，按输出 token 看为 4.96 倍。
- 耗时：聚合总代理墙钟为 2,970.2 秒对 1,505.5 秒，约 1.97 倍；平均差 91.5 秒/题，配对 bootstrap 95% 区间 42.9-137.4 秒。配置臂在 16 题中的 13 题更慢，3 题更快；原生臂自身存在 27-183 秒长尾，所以耗时比 token 比更不稳定。
- 工作效率：按正确题数/10 万 total tokens，本库配置约为原生的 10%；按正确题数/分钟，约为原生的 51%。在这类短任务上，完整配置的自动路由、技能正文读取、目标管理和收尾验证形成了显著固定成本。

**结论**
本库 agent 配置适合复杂、多阶段、需要日志/恢复/范围控制的仓库任务；但对短小、单文件、一次成型的算法题，它相对最小原生提示没有测到正确率优势，同时消耗约 10 倍 token、接近 2 倍墙钟时间。若目标是批量短代码生成，应优先使用最小提示；若目标是长链路工程交付，应使用完整配置，但需要把步骤预算、技能读取和收尾成本纳入容量规划。

**限制**
- HumanEval 不能衡量长上下文仓库定位、跨文件修改、测试修复、回滚、日志和恢复能力。
- 16 题样本只适合识别大效应，不适合精确估计很小的正确率差异。
- 墙钟包含 provider 排队和网络波动；token 指标更稳定。
- 这里的“原生”是同 launcher/同模型的最小提示对照，不是替换为另一个原生默认模型的比较。

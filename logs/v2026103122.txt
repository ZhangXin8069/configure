# gback 子模块状态修复

## 根因
当前 Git 2.34.1 在父仓库仅存在子模块指针变化时，`git stash push --all` 会以退出码 0 返回，但输出 `No local changes to save` 且不创建 `refs/stash`。`gback.sh` 因此进入“stash 未创建”的保护分支并中止。

## 改动
- `bin/gback.sh` 检测到 gitlink 变化时，使用临时索引合成完整工作树快照，不再依赖普通 stash 对子模块指针的忽略行为。
- 使用带 reflog 的 `refs/stash` 写入方式，确保首次创建和后续 stash 都有可用的 `stash@{0}`。
- 重置前检查已初始化子模块内部是否干净；若存在未提交内容则安全中止，避免 reset 丢数据。
- reset 后使用 `git submodule update --recursive --checkout` 将已初始化子模块对齐到父仓库记录的提交，并提供子模块指针恢复命令。
- `bin/gback.test.sh` 新增父子仓库回归夹具和组合状态测试；`bin/AGENTS.md` 同步行为说明。

## 验证结果
- `bash -n bin/gback.sh bin/gback.test.sh`：通过。
- `bash bin/gback.test.sh`：8 个场景全部通过。
- `form-audit --strict --quiet`：通过。
- `form-data-tracking-check --quiet`：通过。
- `git diff --check`：通过。

## 限制
子模块内部的 tracked/untracked/ignored 修改不会被本脚本递归 stash；遇到这种状态会明确中止，而不是执行可能丢数据的 reset。

## 后续步骤
重新运行 `gback.sh`。当前 `refer/git-rep/oh-my-codex` 的 gitlink 差异会进入 stash，工作区随后对齐 upstream；若之后需要恢复该子模块指针，按脚本输出的 `stash apply`、`checkout stash@{0} -- <子模块路径>`、`submodule update` 三步执行。

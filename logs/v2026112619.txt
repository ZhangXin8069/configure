改动分三块。

**1. lib/_wsl/setup.md（过严限制与顺序）**
- 标题去掉“WSL 2”限定，首段区分 WSL 产品版本（`wsl --version`，2.x/3.x）与发行版架构（`VERSION` 只有 1/2），并明确 `--set-default-version 2` 的 2 是架构不是产品版本，安装 WSL 3 也无需改它。
- 安装顺序改为 `--list --online` → `--install -d` → `--manage --move` → `--set-default` → `-d` 进入；原来 `--set-default Ubuntu` 出现在发行版安装之前。
- conda 一节拆成 7 个编号步骤，`conda init zsh` 排在 Miniforge 安装、镜像配置、工具链之后，并说明 `sh_init.sh -z` 会用模板覆盖 `~/.zshrc`，因此 `conda init` 必须在其后。
- Shell 部署补 `sudo apt install zsh`：`sh_init.sh -z` 在缺 zsh 时会静默跳过 `.zshrc`。
- `import-in-place` 的 `Test-Path`/`--list` 提到 `--shutdown` 之前；压缩段的 `DistributionName`、`/etc/wsl.conf` 与 GPU 示例统一为 `<发行版>` 占位符；去掉冗余 `--version 2` 并说明何时需要。

**2. bin/agent-protocol-bridge.py（子代理跑不动的根因）**
- 根因：Codex 0.172 不再把工具放顶层 `tools`，而是放进 input 的 `additional_tools` 项，其中 `functions.exec` 是 `custom` 类型。桥接只读顶层 `tools`，转发给上游的工具数为 0，模型只能回“我先执行…”，子代理表现为不连续、无法完成工作。
- 修复：从 `additional_tools` 收集并展平 namespace/custom 工具，名称保持裸名（`exec`/`wait`/`sleep`，Codex 按裸名路由）；custom 声明为只接受 `input` 字符串的函数，回复还原成 `custom_tool_call` 事件（用 `function_call` 会被判 `incompatible payload`）；回放历史时把 `custom_tool_call`/`custom_tool_call_output` 映射为 assistant `tool_calls` 与 tool 消息。
- 验证：mock 上游确认 `functions.exec` 脚本真实执行（exit_code 0）；真实 `co dgo` 子代理返回 `REAL-LINK-OK`，日志含 2 条 `command_execution`。`agent-protocol-bridge.test.py` 10 项通过（新增 2 项）。

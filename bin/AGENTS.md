# AGENTS.md — bin 工具脚本

工具 shell 脚本目录。`bin/` 由 `env.sh` 前置到 `PATH`，所有 `.sh`（含 `cl`/`cls`/`op`/`co`/`ops`/`cos` 等符号链接）可直接按名调用（`gpush.sh`、`ssub.sh`）。脚本必须可执行且带 shebang。

## 脚本骨架约定

```bash
#!/usr/bin/env bash
_PATH=$(cd "$(dirname "${BASH_SOURCE[0]:-$0}")" && pwd)
_NAME=$(basename "${BASH_SOURCE[0]:-$0}")
echo "###${_NAME} in ${_PATH} is running...:$(date "+%Y-%m-%d-%H-%M-%S")###"
# ... 逻辑 ...
echo "###${_NAME} in ${_PATH} is done......:$(date "+%Y-%m-%d-%H-%M-%S")###"
```

- 必须用 `${BASH_SOURCE[0]:-$0}`（不能用裸 `$0`，登录 shell 下 `$0` 为 `-bash` 会报错）
- 执行首尾打印带时间戳标记
- 严格模式 `set -euo pipefail` 仅部分新脚本使用
- **所有 `.sh` 脚本必须有可执行权限**（新建/编辑脚本后执行 `chmod +x <script>`）

## 平台与注意事项

- `.bat`/`.ps1` 为 Windows 对应版，**不**被别名生成器扫描（只扫 `.sh`）；`agent-protocol-bridge.py` 当前仅在 Unix `agent.sh` 启用，Windows 对 `bridge_models` 明确提示改用 `op`，不发起必然失败的直连请求
- `agent.bat` 只负责识别 launcher 名称和转交 PowerShell；`agent-runtime.ps1` 实现与 Unix 版一致的 `data/runs/<run-id>/` manifest/state/context/events、文件锁、session/thread 恢复、`--once`/`--max-turns`/`--max-runtime`/`--stop-file`/`--resume` 和四系 headless 驱动。恢复前会校验 schema、agent、launcher 与 workspace 身份；Windows 需要 `powershell.exe`（或 `pwsh.exe`）；本机 Unix 测试只能做静态检查
- `agent-prompt.txt` 为 cl/op/co/cm 四系（Unix `agent.sh` + Windows `agent.bat`）的 **prompt 单一来源**（`oopencode-prompt.txt`/`ccodex-prompt.txt` 为指向它的符号链接）；保留 `${HOME}`/`${_PWD}` 占位符（op 另支持 `${LIST_FILE}`），运行时替换；**修改 prompt 只改此文件**，勿在脚本内再内嵌。首行固定为「你是一个多身份智能体…」，`agent.test.sh` 用它区分完整 prompt 与 minimal dispatch，**不得改动该首行**。结构上分三级效力：【规则效力】声明 ⛔ 硬闸门 > 准则 > 建议的优先序；四个 ⛔ 闸门分别是【请求不阻塞任务推进】（非破坏性请求按类型自动取默认项：同意/第一项/继续/知情/L2）、【五类必须显式确认的操作】（删除文件、force push、改写已推送标签、修改系统配置、对外发布）、【访问边界】、【输出前自查清单】。显式写明的常规操作（本地 commit、push、创建标签、推送非改写标签）一律直接执行不得询问。文末【冲突裁决】固定为 安全边界 > 用户显式指令 > 本提示词 > 技能规范 > 模型默认习惯；`agent.test.sh` 对上述锚点做回归断言。
- **agent 驱动模式**（Unix/Windows 语义一致）：`-file/--file PATH` 指定指令文件（cl/op 支持，co 不支持），`-time/--time DUR` 指定「继续」间隔（默认 30s；支持 `30`/`30s`/`5m`/`2h`）。`--once` 执行一次 prompt（及可选文件指令）后结束；`--max-turns N`、`--max-runtime DUR`、`--stop-file PATH` 提供显式上限与外部停止；`--resume RUN_ID` 从 data manifest 复用已有 session/thread。V1 op 使用 `opencode run --agent build --auto` 并从 `session.id=` 解析会话；V2 op 使用 `opencode run --standalone --agent build --format json --model <provider/model#variant>`，从 JSON `sessionID` 解析会话，续链统一以 `run -s` 完成。co=`codex exec --json`、cl=`claude -p` 链不变——先发 prompt 并等回合完成，再把文件内容作为首条指令（若有），之后按间隔发送「继续」，默认最多 100 次继续回合；不给驱动选项时保持原生 TUI（V1 op TUI 传 `--agent`，V2 顶层没有该参数，改由 `default_agent` 配置选择；其余注入语义不变）。驱动期间后台 `tail -F` 监视 data run 日志并输出关键活动行
- 模型与覆盖（两层默认：**显式选途径时 providers 层优先，否则 agent 层优先**，高优先层缺值回退另一层）：显式选途径指命令行供应商快捷词或 `{CLAUDE,OPENCODE}_PROVIDER`/`CODEX_PROVIDER_ID`/`COMMANDCODE_PROVIDER` 环境变量（一视同仁）。故 `--model`/`--variant`/`--reasoning-effort`/`--effort` 及同名环境变量恒为最高；其后模型按「显式途径 ? `providers.<途径>.default_models.<agent>` : `agents.<agent>.model`（agent 自身默认模型，未显式选途径时优先）」择序；强度同序：命令覆盖 > 〔显式途径 ? `providers.<途径>.default_strengths.<agent>` : `agents.<agent>.strength` > 旧键（`agents.opencode.variant`/`agents.codex.reasoning`/`agents.claude.env.CLAUDE_CODE_EFFORT_LEVEL`）〕> 另一层 > `max`；两层皆空则启动报错（退出码 64）；途径由供应商快捷词、上述环境变量或 `agents.<agent>.provider` 决定；**供应商快捷词仅保留** `pay`/`go`/`gt`（或完整名 `deepseek-pay`/`opencode-go`/`commandcode-goat`），可出现在任意参数位置（如 `cl go`、`co pay`、`cm gt`）；`{OPENCODE|CODEX|CLAUDE|COMMAND_CODE}_BIN` 指定二进制（未指定回退 PATH）、`{OPENCODE|CODEX|CLAUDE|COMMANDCODE}_MODEL`/`--model MODEL` 直接覆盖模型；op 另支持 `--variant LEVEL`（经 `OPENCODE_CONFIG_CONTENT` 注入）、co 支持 `--reasoning-effort LEVEL`/`--sandbox`/`--ask-for-approval`（默认 `danger-full-access`/`never`）、cm 支持 `--effort LEVEL` 与 Command Code 原生权限模式；co 的 provider/TUI 配置、op 的 agent 名或 cl 的权限模式等默认值见下条配置来源（**原短旗标 `-m/-o/-p/-q/-k/-g/-f/-h` 及 `*_DEFAULT_MODEL_FLAG`、`*_MODEL_M/O/P/Q/K/G/F/H` 已移除**）
- **OpenCode V2 兼容层（2026-11-02）**：启动器以 `opencode --version` 主版本自动分流。V2 不写 V1 的 `agent` 字段，而经 `OPENCODE_CONFIG_CONTENT` 注入原生 `model`、`default_agent`、`agents.<id>.model=<provider/model#variant>`、`update` 和按已设置 key 生成的 `providers.<id>.options.apiKey`；`deepseek-pay`、`opencode-go` 与 `commandcode-goat`（OpenCode provider id `commandcode`）均使用 V2 内置 provider。V2 命令统一加 `--standalone`，避免共享后台服务复用旧配置。V2 顶层 TUI 不接受 `--agent`，由 `default_agent` 选择；headless `run` 显式传 `--model provider/model#variant --agent ... --format json`，日志级别用 V2 接受的小写 `debug`。会话导出改用 `opencode session export`，用户输入兜底同时解析 V1/V2 export 结构。`lib/_open-code/install.sh`/`install.bat` 改从 OpenCode V2 官方版本源安装；`config.sh` 在 V2 写 `permissions`、`plugins`、`cli.json`，V1 保留旧字段兼容。

- **环境里没有对应 agent 可执行文件时自动安装**：非 root 服务器、新机器、只读共享部署首次使用时，启动器自动运行部署内 `<configure 根>/lib/_<组件>/install.sh`（claude→`_claude-code`、opencode→`_open-code`、codex→`_codex`、commandcode→`_command-code`；均默认装入 `${HOME}/.local/bin`），成功后把安装目录前置到 PATH 并继续启动。`AGENT_AUTO_INSTALL=0` 关闭，`AGENT_INSTALL_DIR` 覆盖目录；失败只尝试一次。Windows 端语义一致。

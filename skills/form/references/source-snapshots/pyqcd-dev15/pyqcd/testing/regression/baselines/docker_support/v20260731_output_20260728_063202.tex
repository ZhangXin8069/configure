\begin{abstract}
本报告对 \texttt{docker-v20260731}（GPU双精度 complex128）与 \texttt{docker-v20260730}（GPU单精度 complex64）两版管线在 L24x72（$\beta=6.20$, $a=0.1053$\,fm）系综上运行完整 disconnected 胶子 PDF 计算的结果进行详细对照。管线包含：(1) 质子二点蒸馏关联函数，(2) 非定域胶子 OPE 算符从头计算，(3) Huangcl 风格比 $R(z)=\langle C_{\text{3pt}}^{\text{disc}}\rangle/\langle C_{\text{2pt}}\rangle$ 的 Jackknife 分析。重点对比计算精度、物理结果一致性、GPU 性能与内存开销。
\end{abstract}

\subsection{性能分析}

\begin{itemize}[itemsep=4pt]
  \item \textbf{OPE 计算（$\sim 1.6\times$ 减速）}：该比值接近预期的理论值 $\sim 2\times$（双精度每个复数的运算量翻倍，内存带宽翻倍）。CuPy 的 $F_{\mu\nu}$ 构建和 Wilson 线累积在一张 $8$\,GB 的 RTX 4060 GPU 上运行良好。
  \item \textbf{VVV 计算（$\sim 7\times$ 减速）}：远超预期。初步诊断表明 VVV 循环中每时间片的 $\mathtt{einsum}$ 调用生成了许多小 kernel，双精度下的 kernel launch 开销占比更大。此外 $4.6$\,GB 的 CPU 本征矢（vs.\ $3.6$\,GB）导致内存带宽瓶颈。
  \item \textbf{Wick 收缩（$\sim 14.7\times$ 减速）}：性能差异最大。这是 Wick 中大量 $\mathtt{einsum("abc,gjad->gjbcd", ...)}$ 在双精度下的中间张量更大（$8$\,字节/元素 vs.\ $4$\,字节/元素），导致 GPU 内存压力增大，触发更多 (de)allocation 和内存碎片化。
  \item \textbf{conf 6450 Wick 异常慢（$\sim 1.6\times$ 其他配置）}：两个版本均观察到 conf=6450 的 Wick 更慢，可能与 perambulator 的条件数有关。
\end{itemize}

\section{结论与建议}

\subsection{主要发现}

\begin{enumerate}[itemsep=4pt]
  \item \textbf{双精度管线运行正确}：所有物理观测量（有效质量、$R(z)$、OPE算符的虚部消除）与单精度版本完全一致，验证了 \texttt{compute\_2pt\_gpu.py}、\texttt{compute\_ope\_gpu.py} 及本征矢/组态读取组件的正确性。
  \item \textbf{每配置本征矢加载已验证}：按时间切片加载二进制文件（72 个文件 per config，共 $\sim 4.6$\,GB complex128 per config）成功，无 NaN/Inf。
  \item \textbf{总减速约 $9\times$}：在 RTX 4060 (8 GB) 上，双精度管线比单精度慢约 9 倍。OPE 减速 $\sim 1.6\times$ 符合预期，但 VVV/Wick 的额外减速可能与当前实现中过多的中间张量分配有关。
  \item \textbf{主要瓶颈：Wick 收缩 (78.6\%)}：是优化的首要目标。
  \item \textbf{所有中间结果已保存}：VVV 块、$F_{\mu\nu}$ 张量、OPE 组件的 .npy/.npz 文件均保存在输出目录中，可用于增量重跑和调试。
\end{enumerate}

\subsection{优化建议}

\begin{enumerate}[itemsep=3pt]
  \item \textbf{Wick 收缩}：将 72 个时间源的双重嵌套循环替换为 cuTENSOR 或 batch GEMM 内核，或将部分中间张量预计算并缓存在 GPU 上以减少冗余分配。
  \item \textbf{VVV 计算}：当前实现按 $x$ 方向循环调用 $\mathtt{einsum}$。改为在所有空间维度上的单次 batched 收缩可将 kernel launch 次数减少 $\sim 24\times$。
  \item \textbf{内存管理}：每个配置的 VVV 和 $F_{\mu\nu}$ 在保存后可从 GPU 卸载，释放约 $1.5$\,GB 的 GPU 内存供下一个配置使用。
\end{enumerate}

\subsection{下一步计划}

\begin{itemize}[itemsep=2pt]
  \item 在 3 个配置以上的系综上运行（或利用 VVV 缓存对更多配置运行以确保更好的统计量）
  \item 整合完整的 LaMET 微扰匹配核，从 $R(z)$ 导出光锥 PDF $g(x,\mu)$
  \item 对动量列表（如 $P_z=-3,-4,-5$）进行扫描以改善傅里叶变换基底
  \item 探索利用 CUDA Graphs 或 cuQuantum 在 A100/H100 GPU 上加速 Wick 收缩
\end{itemize}

# report 内容与视觉指南

本文件是 `report` 技能的内容设计 reference。生成任何成稿前完整读取；它把“学术展示/组会汇报”约束成可检查的
逐页信息单元，避免把长报告机械压缩成一串文字页。

## 1. 汇报的最小闭环

学者、导师或同行通常需要在有限时间内判断：问题是否重要、当前工作是否推进、证据是否可信、下一步是否值得投入。
因此主体叙事沿着下面的闭环组织：

```text
研究问题/假设
      ↓
阶段目标与验收标准
      ↓
方法/算法/物理模型
      ↓
可复现实验或计算设置
      ↓
关键结果与验证
      ↓
当前结论 + 剩余风险
      ↓
下一步可验收产物 + 受众请求/导师决策
```

每张主体页是一个完整的“结论—证据—含义”单元：

| 槽位 | 要写什么 | 合格判据 |
|---|---|---|
| 结论标题 | 本页最重要的判断，尽量带方向/变化 | 不写“实验结果”“方法介绍”这类栏目名 |
| 主视觉 | 图、表、流程、算法图、公式或框图 | 去掉视觉旁文字后，关系仍可读 |
| 证据 | 数据、代码行为、公式依据、对照条件 | 有来源、单位、基线或证据等级 |
| 含义 | 这页改变了什么判断 | 能连接到下一页或下一步 |
| 请求/风险 | 需要受众判断、导师决策或当前阻塞 | 没有请求时明确写“无需决策” |

## 2. 推荐逐页骨架

不要无条件生成全部页；按材料和汇报时长选用。默认 10–15 分钟使用 8–12 张主体页，详细推导和完整数据
进入附录。每张页只保留一个主结论。

| 页型 | 必须回答 | 主视觉优先级 | 常见误区 |
|---|---|---|---|
| 标题/目标 | 今天要解决什么、处于哪个阶段 | 一行目标或极简任务框 | 放大标题却没有目标 |
| 结论先行 | 已完成什么、最强证据、要什么决定 | 三栏状态卡或结论框 | 把结论藏到最后 |
| 问题与判据 | 假设、输入、成功标准是什么 | 问题树、逻辑框图、指标表 | 背景铺陈过长 |
| 总体流程 | 从输入到结果如何走 | TikZ 流程图/系统框图 | 节点写成段落 |
| 算法/模型 | 关键状态、循环、停止条件或方程链 | 算法图、伪代码图、公式 | 只写算法名称 |
| 设置与基线 | 数据、参数、设备、对照是否可复现 | 紧凑参数表/实验矩阵 | 缺单位、样本数、基线 |
| 关键结果 | 哪个量变好/变坏，幅度多大 | 曲线、柱状图、结果表 | 图例无基线或结论标题 |
| 验证与风险 | 结果是否稳健、哪里还不可信 | 消融表、误差框图、边界流程 | 把未测写成已证实 |
| 阶段结论 | 主张、证据、置信度和影响 | 四格结论框/映射表 | 只重复结果，不说明影响 |
| 下一步与请求 | 任务、产物、日期、阻塞、决策 | 时间线/甘特图/决策树 | “继续优化”没有验收标准 |
| 附录 | 如何回答追问 | 推导、完整表、代码证据 | 把主体应有证据全部藏进附录 |

建议每页在草稿阶段使用以下记录格式：

```text
frame_id=S<n>  结论标题：<一句可判断的话>
主视觉：<流程图/算法图/表格/公式/图表/框图>
证据：<E<n>，文件:行号/命令/结果文件>
布局：width_budget=<行内/单列/整页>；height_budget=<短/中/高>；min_font_pt=<实测/模板值>
完整性：split_allowed=<是/否>；split_boundary=<语义边界>；expected_page=<页号>
风险：<长公式/路径/URL/表格列/TikZ 外框/彩色框/页脚>；缓解：<局部处理>
含义：<对项目判断的影响>；下一页接口：<需要解释的前提或要做的行动>
```

`analy`/`pure` 交付的密集对象沿用 `content_payload` 字段：
`content_id | claim_id | evidence_ids | visual_type | width_budget | height_budget | min_font_pt |
item_count | split_allowed | split_boundary | risks | mitigation`；`item_count` 填公式行、表格行、代码行或 TikZ 节点数，
TikZ 的 `risks` 必须把节点外框、路径标签、独立标签和箭头分别列出。

## 3. 视觉表达决策表

先写主张，再选视觉；不能先画装饰图再寻找含义。

| 主张关系 | 首选表达 | 必须出现的元素 | 适用边界 |
|---|---|---|---|
| 顺序、依赖、输入输出 | 流程图 | 节点、箭头、输入、输出、关键判定 | 节点多于 7 个时拆总览与细节 |
| 迭代、分支、停止 | 算法/伪代码图 | 初始化、状态、循环体、分支、停止条件 | 省略实现细节，但不能省略判据 |
| 模块、层级、物理对象 | 框图/映射表 | 边界、接口、符号与对象 | 关系不清时不用纯列表 |
| 多方案、基线、参数 | 表格 | 统一字段、单位、基线、差异 | 一页超过约 6 行时按语义拆页 |
| 因果或定量关系 | 公式/公式链 | 定义、假设、单位、极限或误差 | 长推导分“主链页+附录证明页” |
| 数值趋势和比较 | 曲线/柱状图/结果表 | 坐标单位、样本/误差、基线、结论 | 只画有真实数据和明确比较的问题 |
| 时间、依赖、选择 | 时间线/甘特/决策树 | 可验收产物、日期、阻塞、分支条件 | 不用“持续优化”替代任务 |

### 3.1 流程图/框图

- 节点写“对象 + 动作”，如“原始数据 → 清洗并分层”，而不是“步骤一”。
- 箭头只表达一种关系：数据流、控制流或依赖关系；不同关系使用文字或线型区分。
- 主流程保持 4–7 个节点；细节放下一页或附录。每个节点尽量不超过两行。
- 结论页可用“已完成 / 当前瓶颈 / 下一步”三框图，但每框必须有证据或验收产物。

### 3.2 算法图/伪代码图

算法页必须让学者/导师能回答“输入是什么、状态怎么变、何时停止、输出如何验证”：

```text
输入与约束
    ↓
初始化状态 S₀
    ↓
计算候选/更新 Sₖ ── 不满足判据 ──┐
    ↓                              │
满足停止/收敛判据？ ───────────────┘
    ↓
输出 + 验证指标 + 复杂度/误差
```

不要把完整程序截图放在主体页；用 TikZ 重绘逻辑并在页脚给出原代码 `文件:行号`。逐行代码只在附录
出现，且使用 `\lstinputlisting` 直引，避免代码与源文件漂移。

### 3.3 公式与物理/数学内容

公式不是装饰。主公式旁同时给出符号表或一行物理含义；推导按“定义/对称性/近似/边界条件/量纲”标注依据。
主页面只保留足以支持结论的公式链，完整证明放附录。涉及极限、退化或守恒量时至少做一次可读的检查。

### 3.4 表格与结果图

- 表格字段按“影响受众判断”的顺序排列；把长句改为关键词，把解释放在表格下方。
- 每个数值带单位；相对变化写清分母/基线；误差写清统计/系统含义（若未知则标未验证）。
- 曲线最多保留能支撑结论的系列；图例、坐标、样本数和基线不能被删掉。
- 结果页标题直接写方向性结论，如“加入 X 后误差下降 18%，但 Y 区间仍未验证”，而不是“实验结果”。

## 4. 信息密度与拆页规则

下面的内容预算服务于 `frame_manifest`，不是凭感觉填页；它不能替代编译和逐页渲染检查：

### 4.1 版式账本硬闸门

- `columns` 必须记录实际宽度：`\sum_i w_i+(n-1)\columnsep\le0.96\linewidth`；百分比之和小于 1
  不代表加入列间距后安全。
- 高度预算必须扣除 frametitle、正文上/下留白、来源行、footline 安全区和盒体内距；`\vfill` 不能作为
  解决超载的手段。超载按“删装饰/重复 → 细节下沉 → 语义拆页 → 局部间距”处理。
- TikZ 预算覆盖节点外框、箭头、标签和 `text width` 的实际包围盒；最右、最下对象须留安全边距。
  `\node`、路径上的 `node{...}` 标签、独立文字标签和箭头均视为独立包围盒；标签优先使用
  `above/below/left/right=<安全间距>`，长文本设置 `text width`/`align`，不能压入节点或箭头端点；
  表格文本列统一使用 `>{\raggedright\arraybackslash}`，长路径不得放不可换行的固定列。
- 主体正文、表格和主视觉不得以 `\tiny` 降密度；记录 `min_font_pt`，`\tiny` 仅可用于不承担主信息的
  图内标签且仍须通过投影可读性检查。
- 交付检查结果必须同时给出：`pages_expected / pages_actual / pages_rendered / pages_checked`、
  `overfull_hbox / overfull_vbox / underfull`、`occlusion_pairs / clipped_objects / outside_safe_area`。
  警告为零不是遮挡为零的替代品。

### 4.2 内容密度建议

| 元素 | 主体页建议上限 | 超出时的动作 |
|---|---:|---|
| 主结论 | 1 条 | 把次要结论移到下一页 |
| 主视觉 | 1 个，必要时 2 个同源小视觉 | 拆为总览/细节或主图/表格 |
| 文字要点 | 3–5 条，每条尽量一行 | 删除背景句，改成标签或图中节点 |
| 表格数据行 | 约 6 行 | 按方案、阶段或指标拆页 |
| 流程/算法节点 | 4–7 个 | 总览页保留主链，细节页展开 |
| 公式行 | 约 3 行 | `aligned` 分行或另设推导页 |
| 页脚来源 | 1 行 | 缩短路径显示，正文保留可追溯 ID |

拆页顺序：

1. 先删除装饰、重复标题、泛泛背景和不影响判断的原始细节；
2. 再把“方法总览 / 方法关键步骤”“结果趋势 / 结果稳健性”等天然语义边界拆开；
3. 重复页标题中的关键主语和进度标识（如“核心算法（1/2）”），保持上下文完整；
4. 最后才调整列宽、间距和字体，禁止用 `\tiny`、整页 `\resizebox` 或裁掉来源来掩盖超载。

主体页不使用 `allowframebreaks`。表格不能在任意行间断开，公式推导不能在等号链中间断开，流程图不能
把箭头终点放到下一页。附录也优先手动拆成有标题的 frame。

## 5. 证据与状态标识

统一使用三态：

| 状态 | 含义 | PPT 写法 |
|---|---|---|
| 确证 | 直接由代码、实测输出或核验公式支持 | `证据：...` + 来源 |
| 推断 | 由证据合理推出，但不是直接观测 | `判断：...`，注明推断依据 |
| 未验证 | 尚未运行、数据不足或来源不完整 | `未验证：...`，给出补测/核验动作 |

来源至少包含一种可复查指针：`文件:行号`、执行命令、结果文件、数据集/配置名或文献章节。图表页脚只显示
短来源 ID，附录/参考页再给完整路径；这样能兼顾投影可读性和可追溯性。引用代码时以源文件为准，不能把
手写伪代码冒充实测实现。

## 6. “绝对干货”过滤器

保留一项内容前逐项问：

1. 它是否帮助定义问题或验收标准？
2. 它是否解释关键方法、算法状态或物理量关系？
3. 它是否提供当前结论的证据、基线或误差？
4. 它是否暴露会改变决策的风险/缺口？
5. 它是否对应下一步可验收产物或需要受众/导师做的决定？

五项都否定的内容删掉。装饰性图标、长篇项目背景、没有结论的代码截图、重复的“工作很顺利”、没有日期和产物的
计划，以及没有真实数据的趋势图都不能进入主体。

## 7. 成稿前检查

- [ ] 任务定义写明受众、时长、主问题、阶段目标和产物。
- [ ] 每张主体页都有结论标题、主视觉、证据来源和含义；标题不只是栏目名。
- [ ] 至少约 80% 主体页以流程图、算法图、框图、表格、公式或图表承载核心信息。
- [ ] 所有数字有单位、基线和来源；确证/推断/未验证没有混用。
- [ ] 方法页保留输入、关键状态、判定/停止条件和输出验证；结果页保留误差或局限。
- [ ] 长表、长公式和长流程按语义拆页，未使用主体 `allowframebreaks`。
- [ ] `frame_manifest` 的预期页数、实际页数、渲染页数和人工检查页数一致；布局预算覆盖列间距、来源和页脚安全区。
- [ ] `occlusion_pairs=0`、`clipped_objects=0`、`outside_safe_area=0` 均有逐页渲染证据；必要时用 `\overfullrule=5pt` 诊断。
- [ ] 下一步有日期/产物/验收标准，受众请求写成可选择的决策题。
- [ ] PDF 编译与渲染检查通过，主体页没有溢出、遮挡或不可读的字号。

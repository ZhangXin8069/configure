# AGENTS.md — skills 技能目录

agent 技能库。每个技能一个子目录，内含 `SKILL.md`（frontmatter + 正文）。输入形如 `{~skill-name}` 时执行 `skills/skill-name` 对应技能。

## 日志预读策略（全局约定）

所有技能会话预读历史日志（`.X.<时间戳>.log`）时遵循**关键信息速览**策略：

- 只读**最新 1 份**日志的**尾部汇总区**（`tail -20` 上限），不列多份、不逐份追加
- 只提取关键信息：上次任务/对象、结论或收敛结果、遗留项与下一步建议
- 不做深入解析：过程轮次、命令细节一律跳过，不做逐行 think；总耗时以秒级为限
- 无历史日志（首次运行）时正常跳过，不视为错误；只读不改

## 前置上下文预读（全局约定）

所有技能会话**第一步**与历史日志预读同步，只读当前工作目录的**说明文件**与 **agent 文件夹**
（清单可扩展，存在即读、缺失即跳过，不视为错误），只取关键信息、避免耗时过长：

- **说明文件**按优先级取第一个存在的：`AGENTS.md` > `README.md` > `CLAUDE.md` > `AGENT.md` >
  `CODEX.md`，`head -40` 限行读取关键区（项目约定/命令/目录结构/入口点/测试方式）；
- **agent 文件夹**按优先级取第一个存在的：`.opencode` > `.claude` > `.codex`，只列顶层结构
  （`ls | head -10`），内含 `AGENTS.md` 时 `head -20` 读取；
- 全程只读不改；总耗时以秒级为限。

各技能 SKILL.md 的「历史日志预读」章节内含「前置上下文预读」小节（命令示例与细则）。

## AGENTS.md 同步约定（全局约定）

所有技能会话中如发现**当前工作目录的 AGENTS.md** 缺失本次任务相关且对后续会话
有益的内容（项目约定/命令/目录结构/入口点/测试方式/新功能说明），**必要时补充更新**，
保持约定文档与仓库状态同步（与 init 的 AGENTS.md 维护职责衔接，此处为任意技能的通用补充）：

- 只补充**确凿有益**的内容：本次任务确立的约定、验证过的命令、新入口点/结构变化；
  不写入个人化/临时性/未验证内容；
- **最小改动**：在既有章节内补充或新增小节，遵循原文档结构（表格/列表），不重写全文；
- **先读后写**：写入前先读 AGENTS.md 现状，避免重复条目与格式破坏；
- 改动不代提交（提示用户自行 git add/commit）；补充位置与内容记入会话日志。

各技能 SKILL.md 的「前置上下文预读」小节后含「AGENTS.md 同步」小节（细则相同）。

## TODO 生成与实时更新约定（全局约定）

所有技能会话**执行第一步**必须用 **todowrite 工具**生成**详细 TODO 列表**（吸收 Anthropic 官方
skill-creator "add steps to your TodoList"）：按任务分解为可独立验证的子步骤、
按依赖排序，**每完成一个子步骤立即调用 todowrite 更新状态**（进行中/完成），
收尾时核对全部完成——详细 TODO 防漏步（多步骤任务的隐性步骤易被跳过），
也是进度证据，0 交互模式（auto）下尤其必要。各技能 SKILL.md 均内嵌本约定。

## 跨技能调用约定（全局约定）

所有技能**必要时可调用其他技能**（范式）：每个技能 SKILL.md 的「触发时机」章节
均含「与其他技能配合」条目，说明该技能在何种情形下调用哪些技能；个别技能有
**默认编排流程**（如 tag 默认 `~diff → ~init → ~tag`，make 编排全部技能）。调用规则：

- 按需调用，不强制：任务确实需要时才调用（打标前看改动 → diff、报错 → debug、
  优化后验证 → test），避免无意义的技能链；
- 被调用技能按其 SKILL.md 规范执行（TODO、日志、历史日志预读等约定一并生效）；
- 新增/修改技能时须维护「与其他技能配合」条目，保持范式完整（19/19）。
- **并行优先**：任务含 2+ 个独立子任务（无共享状态/无顺序依赖/互不改同文件）时，
  优先调用 `dispatch` 并行派发（多独立失败排查、多文件调查、多目标审查、多用例测试），
  单任务或任务有依赖时不并行。

## 技能表同步约定（强约束，全局约定）

**所有技能的核心点必须登记在技能表中**（下方「技能」节的 `| 技能 | 用途 |` 表）：

- 每次**新增**技能：登记技能表（用途行，概括核心能力与产出）+ 互鉴表（标志性优点，
  如适用）+ 技能计数更新（18/18 → 19/19 等）；
- 每次**更改**技能（SKILL.md 核心流程/产出/命名变化）：同步更新技能表对应行，避免
  表格与实际技能脱节；仅措辞级微调可不动表格；
- 技能表行须概括核心点：做什么 + 关键机制（如 analy 的 15 步框架、pure 的三态闭环、
  test 的声明闸门）——"每个技能的核心点都被记录"是本目录硬性约定；
- 本约定由 up/skill-creator/make/all 等流程执行时落实，任意技能会话发现脱节时
  可顺手修正（先读后写、最小改动）。

## 技能范式总览（19 个技能的统一范式）

所有技能遵循同一文档结构与执行范式，新增/修改技能时必须对齐：

**文档结构**（frontmatter + 固定章节序列）：

| 部分 | 内容 |
|---|---|
| frontmatter | `name`（小写连字符，与目录名一致）+ `description`（做什么 + 何时使用，触发词覆盖"pushy"）+ `metadata.openclaw.emoji` |
| TODO 管理 | 执行第一步用 todowrite 生成详细 TODO，逐步更新（见全局约定） |
| 核心原则 | 5-9 条，解释 why 而非堆 MUST |
| 会话日志 | `.X.<时间戳>.log` 不入库、全程追加、分隔行标记、命令记 `$ <cmd>` + `exit=<码>` |
| 历史日志预读 + 前置上下文预读 + AGENTS.md 同步 | 历史日志只读最新 1 份尾部汇总区（tail -20 上限）；前置只读工作目录说明文件（AGENTS.md/README.md/CLAUDE.md 等，head -40）与 agent 文件夹（.opencode/.claude 等，ls 限行）；AGENTS.md 缺失有益内容时必要时补充（最小改动、先读后写）；均只取关键信息、秒级耗时 |
| 触发时机 | 触发词/场景清单 +「与其他技能配合」条目 |
| 工作流程 | Step 1..N，命令给确切可执行示例 |
| 错误处理 | 表格：场景 → 处理 |
| 注意事项 | 边界、安全、日志清理 |

**执行范式**（19 个技能共通的行为准则）：

1. **先问对问题（一次问全）**：需求缺项时，所有问题在第一次交互一次性全部提出，用户一次回答，不逐次追问；
2. **证据驱动 / 诚实**：结论与统计以实测为准（命令输出、退出码、数值），不虚报通过、失败与收益；
3. **声明前自检**：输出"完成/通过/收敛"前，逐项核对有本次会话刚运行的验证输出为证，无证则补跑或标"未验证"；
4. **最小改动**：只改必要处，遵循既有约定，不顺手扩大范围；
5. **循环尝试直至成功**：一次失败不停止，基于新证据分析后重试，直至成功或用户终止；
6. **边界校验**：空输入/越界/退化/极限情形逐一处理（diff 冲突标记、test 数值容差、tag 无标签基线等）；
7. **安全边界**：不越界访问、不代用户提交、触及系统配置前先说明、破坏性操作先警告；
8. **时间戳约定**：`TS=$(date +%Y-%m-%d-%H-%M-%S)`；日志与产物不入库，由用户决定清理。

## 各技能优点互鉴（可供其他技能借鉴的亮点）

| 技能 | 标志性优点（可借鉴处） | 适合借鉴到的场景 |
|---|---|---|
| `init` | 两阶段执行（先只读调查后统一写，避免边扫边改信息丢失）；幂等（重复运行输出"无变更"）；先参考后归档、只复制不移动 | 任何含"先看后改"的批量任务；需保证可重复执行的任务 |
| `tag` | 类型推断 + 独立计数器 + 子版本文法（`stab15_1`）；先推后打、默认同步远程；非必要不确认（展示后直接执行，仅破坏性操作确认）；默认编排流程（~diff → ~init → ~tag） | 需要默认编排其他步骤的技能；有明确消息格式约束的输出 |
| `debug` | 铁律"无根因调查禁止修复"；红旗清单（3 次失败质疑方案本身）；单假设原则（一轮一个假设）；不变量校验（量纲/守恒/边界） | 所有技能的失败处理段（test/all/up 已吸收）；防"盲改"纪律 |
| `optim` | 先测量后优化（3-5 次取中位数）；主导项分析（复杂度/调用开销/IO/启动）；隔离验证（注释嫌疑段对比，同二分思想）；收益量化不虚报 | 任何性能类任务；改进前先立基线 |
| `diff` | 先定范围后执行；先概览（--stat）后详情；边界校验清单（冲突标记/调试残留/未跟踪/二进制/重命名） | 提交前自查、版本对比、任何改动审查的前置步骤 |
| `analy` | 结论附 `文件:行号`（引用前核实）；代码片段 `\lstinputlisting` 直引（逐字节一致）；先全库调查后主题聚焦；多资料"联系与层次"呈现（织网非堆砌）；代码-对象映射（物理图像）；默认引入参考知识库 | 分析报告类任务；需要可追溯证据的文档输出 |
| `pure` | 穷尽性（核心部分清单三态闭环：深挖/浅析/排除，无"未处理"）；独特竞争力定位（纯代码→算法、纯物理→图像与公式、交叉→代码-物理一一对应）；公式推导逐步标注依据+极限/量纲校验；双向映射表无孤儿符号 | 需要"把项目核心挖到底"的深度剖析报告；与 analy 互补（analy 织网、pure 掘井） |
| `test` | 声明闸门五步（IDENTIFY→RUN→READ→VERIFY→ONLY THEN）；中间变量自行计算并保存；产物落盘分层（intermediate/results/figures）；设备切换 + 多精度切换 + 精度转换显式管理 | 任何需要"可复现验证"的场景；数值类项目的环境管理 |
| `make` | 技能编排矩阵（阶段\|调用技能\|关键要求）——编排调用全景；计划表质量要求（bite-sized、无占位符、覆盖/一致性检查）；dry-run 计划表确认后执行 | 多技能协作的复杂任务；任何"先计划后执行"的生成任务 |
| `all` | 收敛判据硬闸门（通过标准/收益<5%/连续两轮无变化/用户终止四判据）；迭代守卫（默认最大 5 轮）；一轮一动作（先 debug 后 optim 分轮）；每轮留证据；失效模式识别（振荡/扩张/低质平台→换方向而非加轮，吸收 agentpatterns.ai 收敛检测） | 任何需要"循环到最优"的任务；防无限空转的资源控制 |
| `plan` | 假设执行者零上下文（计划自包含）；任务间 Consumes/Produces 显式声明接口；任务粒度 = 最小独立测试单元（2-5 分钟）；无占位符铁律；自审（覆盖/占位符/一致性） | 多步骤任务拆解；跨任务命名/接口一致性检查 |
| `review` | 早审查常审查；子代理审查 + 精确上下文裁剪（只给产物信息，不传会话历史）；问题分级 Critical/Important/Minor；反馈可反驳（技术推理 + 证据）；接收审查"先验证后实现"（不表演性同意） | 任何提交前质量把关；派发子代理时的上下文纪律 |
| `skill-creator` | 触发描述是唯一机制（写"何时使用"而非总结工作流）；分级披露（SKILL.md <500 行，长内容拆 references/）；规则形式匹配失败类型（明知故犯→禁止式+红旗表，输出形状→正配方）；措辞微测试（必须带无指令对照、≥5 次重复）；触发率评估 60/40 拆分 + 3 次重复 | 文档/指令类内容的结构设计；规则措辞与触发描述编写 |
| `tdd` | 铁律"无失败测试则无生产代码"（先写代码即删除重来）；RED-GREEN-REFACTOR 双强制验证（看过失败、看过通过）；反合理化表 + 红旗清单；修 bug 也是 TDD（先写复现测试） | 新功能/修复实现；防"后补测试"自我欺骗的纪律工具 |
| `brainstorm` | 路径分类（spike/bounded/architectural）按复杂度定产物规模；棘轮单向升级（不降级）；HARD-GATE 批准闸门（简单任务缩短设计不缩短批准）；分节设计按复杂度缩放；红旗表（"太简单不用设计"等自欺借口） | 需求模糊的任务；设计前的假设检视 |
| `auto` | 前缀式包装不重复实现（细节以目标技能为权威）；一次性预授权分级（L1/L2/自定义）实现 0 交互；0 交互 ≠ 0 报告；停滞保护（连续 N 轮无进展换方向）；中断报告含恢复方式 | 无人值守长任务；权限预授权模式可推广到任何自动流程 |
| `go-on` | 多源汇聚（输入清单/日志/git 改动/opencode 会话交叉验证）；无缝优先（opencode 原生 -c/-s/--fork/run -c 会话继续，消息历史与 Todo 天然继承）；孤儿进程先判定进程类（可无缝衔接不中断，避免浪费计算资源）；信息补查循环 3 轮上限防空转 | 任何"接着干"场景；会话中断恢复；新终端续接任务 |
| `dispatch` | 并行派发纪律（2+ 独立任务拆域、同消息派发=并行）；代理指令四要素（问题域/目标/约束/预期输出，不传会话历史）；整合验证不豁免（冲突检查+全量验证+抽查） | 多独立任务的并行提速；派发子代理时的指令构造与整合纪律 |
| `up` | 本地基线先行（不调查就升级是臆断）；网络调研失败一直重试；差距分析表（现状 vs 最佳实践）；元升级（up 适用于自身，不因"元"豁免）；反合理化表（"明显没问题不用验证"等借口） | 技能库/知识库的持续更新；对照外部最佳实践的差距分析 |

## 技能

| 技能 | 用途 |
|---|---|
| `init` | 仓库/目录初始化：逐目录创建/更新 AGENTS.md，归档各 agent 的 init 文件（CLAUDE.md/CODEX.md/.claude 等 → `.X.<时间戳>.bak`），把 agent 生成内容对应的完整 skill 放到上一级 `skills/`；两阶段执行（先调查后写）、幂等、`.init.<时间戳>.log` 会话日志 |
| `tag` | Git 标签管理：`stab<N>`/`dev<N>`/`bug<N>`/`test<N>` 四类独立编号 + 子版本（如 `stab15_1`），含创建/列出/查看/删除/改写；先看后打、默认同步远程、破坏性操作前确认、`.tag.<时间戳>.log` 会话日志 |
| `debug` | 调试/排错：先复现后定位、证据驱动、二分收敛、不变量校验，最小修复并验证闭环（含 git bisect、bash -x/-n 排查） |
| `optim` | 性能/效率优化：先测量后优化、基准驱动、主导项分析（复杂度/调用开销/IO/启动），最小改动、验证闭环，循环迭代至成功 |
| `diff` | 查看/分析代码改动：先定范围后执行、只读不改、先概览后详情、证据驱动、边界校验（工作区/暂存区/版本间对比，含冲突标记、调试残留、未跟踪/二进制/重命名检查），`.diff.<时间戳>.log` 会话日志 |
| `analy` | 仓库分析：只读分析当前 git 库全部文档与代码，解析 `{$用户输入}` 主题，核心目的三视角（主体结构/各部分关系/项目思路），饱和覆盖（全库文件覆盖登记无死角）+深度追问（what/how/why+结论分级），侧重多份资料的联系与层次逻辑、代码-对象映射（如格点代码与粒子物理图像）；主题为具体工作时按 15 步工作全流程框架组织（A 代码/B 物理：目的与准备→输入→输出→框架→关键细节→正确执行→实际执行→实际输出→结果分析（图表/日志）→综合分析→总结→评价→补充→参考源→附录）；结论附参考源（`文件:行号`），代码片段用 `\lstinputlisting` 直引原文件，LaTeX（ctex+xelatex，模板见 references/latex-template.md，Overfull=0 且 Float too large=0 交付）编译带色彩标识的 PDF 输出到当前目录 `docs/`，`.analy.<时间戳>.log` 会话日志 |

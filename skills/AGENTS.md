# AGENTS.md — skills 技能目录

agent 技能库。每个技能一个子目录，内含 `SKILL.md`（frontmatter + 正文）。输入形如 `{~skill-name}` 时执行 `skills/skill-name` 对应技能。

## 参考文件

- `analy/references/analysis-framework.md`：具体工作主题的代码/物理 15 步分析框架。
- `analy/references/report-guide.md`：分析报告主线、色彩、防溢出、交付检查与示例。
- `tag/references/tag-operations.md`：Git 标签创建、查询、删除、改写与区间操作的详细命令。

## 技能执行公共契约（低 token 版）

各 `SKILL.md` 只写技能特有的决策、动作和验收条件；不要复制本节。每次执行按以下顺序：

1. 首步用当前运行器提供的任务跟踪机制建立按依赖排序、可独立验证的 TODO；每完成一项立即更新，收尾核对。
2. 不创建或读取技能过程记录文件；仅按需预读当前目录首个说明文件前 40 行与首个 agent 目录顶层最多 10 项，不递归、不重复读取。
3. 仅加载当前任务需要的技能和 `references/`；简单单步任务不启动 `auto/all` 链，编排技能向子技能只传任务摘要。
4. 有 Git 工作树且有本次文件改动时，先 `git diff --check` 并定向复查；不自动暂存、提交或推送；仅在用户明确要求时按指定范围执行；无 Git 或无改动立即跳过。
5. 需要同步当前 `AGENTS.md` 时先读后写、只补充确凿信息；不删除、不越界。输出“完成/通过”前必须有本次验证证据。

这组规则同时覆盖前置上下文预读、AGENTS 同步、TODO 管理和 Git 检查；技能文件不再实现过程记录读写。

## TODO（任务跟踪）术语约定

本文中的“TODO”是任务跟踪清单的概念名，不绑定具体运行器。执行时使用当前运行器提供的等价机制，
例如 OpenCode 的 TODO/`todowrite`、Codex 的 Updated Plan、Claude Code 的 `todo-tracking`；工具名称不同
不改变建立、更新和收尾核对任务清单的要求。`TODO` 出现在“禁止占位符”的引号、正则或交付检查中时，
表示需要清除的字面占位符，按该上下文处理。

## AGENTS.md 同步约定（全局约定）

按公共契约处理：确有对后续执行有益的新约定时，先读后写、最小补充；不保留临时信息，
不删除、不越界；本次文件改动由工作树 diff 与验证结果承载。

## TODO（任务清单）生成与实时更新约定（全局约定）

具体要求已合并进上方「技能执行公共契约」；各技能首步仍必须使用当前运行器的任务跟踪机制建立并实时更新可验证 TODO。

## 跨技能调用约定（全局约定）

所有技能**必要时可调用其他技能**（范式）：每个技能 SKILL.md 的「触发时机」章节
均含「与其他技能配合」条目，说明该技能在何种情形下调用哪些技能；个别技能有
**默认编排流程**（如 tag 默认 `~diff → ~init → ~tag`，make 编排全部技能）。调用规则：

- 按需调用，不强制：任务确实需要时才调用（打标前看改动 → diff、报错 → debug、
  优化后验证 → test），避免无意义的技能链；
- 被调用技能按其 SKILL.md 规范执行（TODO 任务清单、前置上下文和 Git 检查约定一并生效）；
- 新增/修改技能时须维护「与其他技能配合」条目，保持范式完整（20/20）。
- **并行优先**：任务含 2+ 个独立子任务（无共享状态/无顺序依赖/互不改同文件）时，
  优先调用 `dispatch` 并行派发（多独立失败排查、多文件调查、多目标审查、多用例测试），
  单任务或任务有依赖时不并行。

## 技能表同步约定（强约束，全局约定）

**所有技能的核心点必须登记在技能表中**（下方「技能」节的 `| 技能 | 用途 |` 表）：

- 每次**新增**技能：登记技能表（用途行，概括核心能力与产出）+ 互鉴表（标志性优点，
  如适用）+ 技能计数更新（19/19 → 20/20 等）；
- 每次**更改**技能（SKILL.md 核心流程/产出/命名变化）：同步更新技能表对应行，避免
  表格与实际技能脱节；仅措辞级微调可不动表格；
- 技能表行须概括核心点：做什么 + 关键机制（如 analy 的 15 步框架、pure 的三态闭环、
  test 的声明闸门）——"每个技能的核心点都被记录"是本目录硬性约定；
- 本约定由 up/skill-creator/make/all 等流程执行时落实，任意技能会话发现脱节时
  可顺手修正（先读后写、最小改动）。

## 技能范式总览（20 个技能的统一范式）

所有技能遵循同一文档结构与执行范式，新增/修改技能时必须对齐：

**文档结构**（frontmatter + 固定章节序列）：

| 部分 | 内容 |
|---|---|
| frontmatter | `name`（小写连字符，与目录名一致）+ `description`（做什么 + 何时使用，触发词覆盖"pushy"）+ `metadata.openclaw.emoji` |
| 执行前置 | 引用「技能执行公共契约」，首步任务清单（TODO）、按需加载、验证和 Git 检查不在各技能重复 |
| 核心原则 | 5-9 条，解释 why 而非堆 MUST |
| Git 检查 | 有 Git 且有本次文件改动时执行 `git diff --check` 与定向复查；不自动暂存、提交或推送；无 Git 或无改动立即跳过 |
| 触发时机 | 触发词/场景清单 +「与其他技能配合」条目 |
| 工作流程 | Step 1..N，命令给确切可执行示例 |
| 错误处理 | 表格：场景 → 处理 |
| 注意事项 | 边界、安全、临时产物清理 |

**执行范式**（20 个技能共通的行为准则）：

1. **先问对问题（一次问全）**：需求缺项时，所有问题在第一次交互一次性全部提出，用户一次回答，不逐次追问；
2. **证据驱动 / 诚实**：结论与统计以实测为准（命令输出、退出码、数值），不虚报通过、失败与收益；
3. **声明前自检**：输出"完成/通过/收敛"前，逐项核对有本次会话刚运行的验证输出为证，无证则补跑或标"未验证"；
4. **最小改动**：只改必要处，遵循既有约定，不顺手扩大范围；
5. **循环尝试直至成功**：一次失败不停止，基于新证据分析后重试，直至成功或用户终止；
6. **边界校验**：空输入/越界/退化/极限情形逐一处理（diff 冲突标记、test 数值容差、tag 无标签基线等）；
7. **安全边界**：不越界访问、不代用户执行未授权操作；本次改动按公共契约检查，未经明确要求不代提交或推送；触及系统配置前先说明、破坏性操作先警告；

## 各技能优点互鉴（可供其他技能借鉴的亮点）

| 技能 | 标志性优点（可借鉴处） | 适合借鉴到的场景 |
|---|---|---|
| `init` | 两阶段执行（先只读调查后统一写，避免边扫边改信息丢失）；幂等（重复运行输出"无变更"）；先参考后归档、只复制不移动 | 任何含"先看后改"的批量任务；需保证可重复执行的任务 |
| `tag` | 类型推断 + 独立计数器 + 子版本文法（`stab15_1`）；先看后打、仅用户明确要求时同步远程；非必要不确认（展示后直接执行，仅破坏性操作确认）；默认编排流程（~diff → ~init → ~tag） | 需要默认编排其他步骤的技能；有明确消息格式约束的输出 |
| `debug` | 铁律"无根因调查禁止修复"；红旗清单（3 次失败质疑方案本身）；单假设原则（一轮一个假设）；不变量校验（量纲/守恒/边界） | 所有技能的失败处理段（test/all/up 已吸收）；防"盲改"纪律 |
| `optim` | 先测量后优化（3-5 次取中位数）；主导项分析（复杂度/调用开销/IO/启动）；隔离验证（注释嫌疑段对比，同二分思想）；收益量化不虚报 | 任何性能类任务；改进前先立基线 |
| `diff` | 先定范围后执行；先概览（--stat）后详情；边界校验清单（冲突标记/调试残留/未跟踪/二进制/重命名） | 提交前自查、版本对比、任何改动审查的前置步骤 |
| `analy` | 整体参考层：全库饱和覆盖、主体结构/关系/项目思路三视角、入口与依赖链、证据索引和后续 agent 交接字段；结论附 `文件:行号`，代码片段 `\lstinputlisting` 直引 | 为后续 agent 建立仓库整体导航与可复用分析参考；需要理解全局再进入实现/调试/深挖的场景 |
| `pure` | 细节参考层：消费 analy 的整体接口，核心候选三态闭环，逐算法/物理对象/代码符号深挖，保留公式、复杂度、极限、量纲和双向映射证据 | 为后续 agent 建立核心算法、物理推导与代码—对象对应的可追溯细节参考 |
| `report` | 学者展示层：消费 analy/pure/test 证据，结论—证据—含义—下一步闭合叙事，视觉优先的 16:9 Beamer/PDF，语义拆页与编译/PDF 双重版式验收 | 为学者、导师或同行制作可直接汇报、可独立阅读且证据可追溯的科研展示 |
| `test` | 声明闸门五步（IDENTIFY→RUN→READ→VERIFY→ONLY THEN）；中间变量自行计算并保存；产物落盘分层（intermediate/results/figures）；设备切换 + 多精度切换 + 精度转换显式管理 | 任何需要"可复现验证"的场景；数值类项目的环境管理 |
| `make` | 技能编排矩阵（阶段\|调用技能\|关键要求）——编排调用全景；计划表质量要求（bite-sized、无占位符、覆盖/一致性检查）；dry-run 计划表确认后执行 | 多技能协作的复杂任务；任何"先计划后执行"的生成任务 |
| `all` | 收敛判据硬闸门（通过标准/收益<5%/连续两轮无变化/用户终止四判据）；迭代守卫（默认最大 5 轮）；一轮一动作（先 debug 后 optim 分轮）；每轮留证据；失效模式识别（振荡/扩张/低质平台→换方向而非加轮，吸收 agentpatterns.ai 收敛检测） | 任何需要"循环到最优"的任务；防无限空转的资源控制 |
| `plan` | 假设执行者零上下文（计划自包含）；任务间 Consumes/Produces 显式声明接口；任务粒度 = 最小独立测试单元（2-5 分钟）；无占位符铁律；自审（覆盖/占位符/一致性） | 多步骤任务拆解；跨任务命名/接口一致性检查 |
| `review` | 早审查常审查；子代理审查 + 精确上下文裁剪（只给产物信息，不传会话历史）；问题分级 Critical/Important/Minor；反馈可反驳（技术推理 + 证据）；接收审查"先验证后实现"（不表演性同意） | 任何提交前质量把关；派发子代理时的上下文纪律 |
| `skill-creator` | 触发描述是唯一机制（写"何时使用"而非总结工作流）；分级披露（SKILL.md <500 行，长内容拆 references/）；规则形式匹配失败类型（明知故犯→禁止式+红旗表，输出形状→正配方）；措辞微测试（必须带无指令对照、≥5 次重复）；触发率评估 60/40 拆分 + 3 次重复 | 文档/指令类内容的结构设计；规则措辞与触发描述编写 |
| `tdd` | 铁律"无失败测试则无生产代码"（先写代码即删除重来）；RED-GREEN-REFACTOR 双强制验证（看过失败、看过通过）；反合理化表 + 红旗清单；修 bug 也是 TDD（先写复现测试） | 新功能/修复实现；防"后补测试"自我欺骗的纪律工具 |
| `brainstorm` | 路径分类（spike/bounded/architectural）按复杂度定产物规模；棘轮单向升级（不降级）；HARD-GATE 批准闸门（简单任务缩短设计不缩短批准）；分节设计按复杂度缩放；红旗表（"太简单不用设计"等自欺借口） | 需求模糊的任务；设计前的假设检视 |
| `auto` | 前缀式包装不重复实现（细节以目标技能为权威）；一次性预授权分级（L1/L2/自定义）实现 0 交互；0 交互 ≠ 0 报告；停滞保护（连续 N 轮无进展换方向）；中断报告含恢复方式 | 无人值守长任务；权限预授权模式可推广到任何自动流程 |
| `go-on` | 多源汇聚（输入清单/Git 改动/opencode 会话交叉验证）；无缝优先（opencode 原生 -c/-s/--fork/run -c 会话继续，消息历史与任务跟踪状态（TODO）天然继承）；孤儿进程先判定进程类；信息补查循环 3 轮上限防空转 | 任何"接着干"场景；会话中断恢复；新终端续接任务 |
| `dispatch` | 并行派发纪律（2+ 独立任务拆域、同消息派发=并行）；代理指令四要素（问题域/目标/约束/预期输出，不传会话历史）；整合验证不豁免（冲突检查+全量验证+抽查） | 多独立任务的并行提速；派发子代理时的指令构造与整合纪律 |
| `up` | 四树基线（skills/tools/hooks/plugins）；GitHub/Gitee/GitLab/Codeberg 多源与 star 热榜；API→网页重试降级；差距分析；插件推荐与一键安装器（manifest、marketplace、profile、dry-run、幂等验证）；单轮证据约束自我进化；三查与双目录同步 | agent 配置库的持续更新；对照多平台最佳实践与热榜候选；安全登记和安装外部插件；把可复现经验写回 up |

## 技能

| 技能 | 用途 |
|---|---|
| `init` | 仓库/目录初始化：逐目录创建/更新 AGENTS.md，归档各 agent 的 init 文件（CLAUDE.md/CODEX.md/.claude 等 → `.X.<时间戳>.bak`），把 agent 生成内容对应的完整 skill 放到上一级 `skills/`；两阶段执行（先调查后写）、幂等、可重复运行。 |
| `tag` | Git 标签管理：`stab<N>`/`dev<N>`/`bug<N>`/`test<N>` 四类独立编号 + 子版本（如 `stab15_1`），含创建/列出/查看/删除/改写；先看后打、仅用户明确要求时同步远程、破坏性操作前确认。 |
| `debug` | 调试/排错：先复现后定位、证据驱动、二分收敛、不变量校验，最小修复并验证闭环（含 git bisect、bash -x/-n 排查） |
| `optim` | 性能/效率优化：先测量后优化、基准驱动、主导项分析（复杂度/调用开销/IO/启动），最小改动、验证闭环，循环迭代至成功 |
| `diff` | 查看/分析代码改动：先定范围后执行、只读不改、先概览后详情、证据驱动、边界校验（工作区/暂存区/版本间对比，含冲突标记、调试残留、未跟踪/二进制/重命名检查）|
| `analy` | 整体分析参考：只读分析当前 git 库全部文档与代码，建立全库覆盖、三视角、入口/依赖链和证据索引，解析 `{$用户输入}` 主题；具体主题按 15 步代码/物理框架，结论附 `文件:行号`，LaTeX PDF 输出到 `docs/`，供后续 agent 接续使用|
| `pure` | 细节解析参考：优先消费 analy 的整体参考，只读穷尽核心部分（纯代码向→独特算法、纯物理向→物理图像与公式推导、交叉向→代码—物理一一对应），以三态清单、逐符号/逐公式证据、极限/量纲校验和双向映射形成可复用细节底稿，LaTeX PDF 输出到 `docs/`|
| `report` | 学者科研展示：消费 analy 的整体结构、pure 的核心细节和 test 的实测证据，组织结论—证据—含义—下一步主线；16:9 Beamer/PDF 横板；流程图、算法/伪代码图、框图、表格、公式和结果图主导表达；语义拆页与 xelatex/Overfull/Float too large 双零闸门确保可直接汇报 |
| `test` | 系统化测试：默认测试对象为上次 agent 生成的工作（参考 `.agent.*.list` 格式），可指定项目；中间变量自行计算并保存，中间/最终结果与图表落盘 `test_out/`，失败按 debug 循环修复、通过按 optim 循环优化，支持设备切换（GPU 优先/CPU/NPU）与多精度切换（默认 fp32），数据读写间精度转换显式管理|
| `make` | 项目生成：生成对象为用户指定的项目，编排调用本目录全部技能（init/tag/debug/optim/diff/analy/test）完成全流程（解析需求→调查规划→最小改动实现→系统化测试→循环优化→复查→归档→打标），细节要求为所有技能的汇总|
| `skill-creator` | 技能创建与优化：意图捕获→草稿→测试评估→迭代→触发描述优化；遵循分级披露（SKILL.md 精简、references 拆分）、解释 why 而非堆 MUST、触发描述写"何时使用"；吸收 Anthropic 官方 skill-creator 与 Agent Skills 规范|
| `plan` | 实现计划编写：为多步骤任务编写可执行计划——文件结构设计→任务分解（bite-sized、每任务独立测试周期）→无占位符（禁 TBD/TODO）→自审（覆盖/占位符/一致性）；吸收 obra/superpowers writing-plans 方法论，计划存 `docs/plans/`|

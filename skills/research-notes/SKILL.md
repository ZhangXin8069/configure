# research-notes — 研究记录与接续笔记技能

## 执行前置

遵循当前目录 `AGENTS.md` 的公共契约；仅按需读取本技能正文。

本技能负责把正在进行的实验、推导、测试、调试、讨论和日常工作，整理成**可追踪、可接续**
的 Markdown 笔记。默认产物是 `docs/notes/<主题slug>_<YYYYMMDD>.md`；同日同题重复记录时追加
`_2`、`_3`，保留过程顺序，不覆盖已有笔记。

它记录的是**工作过程**，不是正式展示稿，也不是全库地图：

- 过程记录优先于成稿润色；
- 证据索引优先于叙事扩写；
- 临时结论必须和未验证项分开；
- 结尾必须给后续 agent 一个能直接接手的摘要。

## 核心原则

1. **先记事实，再下结论**：先记录做了什么、看到了什么、改了什么，再写判断。
2. **每条结论都要落证据**：关键判断绑定真实来源，保留文件:行号、命令、输出或原始记录。
3. **分级写结论**：只用 `确证`、`推断`、`未验证` 三态，不把猜测写成事实。
4. **保留过程痕迹**：物理任务保留关键推导链、量纲/极限检查和假设；代码任务保留命令、输入、
   输出、失败现象和修正依据。
5. **增量更新**：同一主题优先追加更新，保持时间线，不为了整洁重写历史。
6. **轻量归档**：只保留对后续决策有用的信息，不扩写成 `report` 式成稿，也不展开成 `analy` 式全景。
7. **可接续**：最后一节必须能直接交给后续 agent，说明当前状态、未完成项和下一步。

## Git 检查

有 Git 且本次会话产生文件改动时，执行 `git diff --check` 和定向复查；不自动暂存、提交或推送。
无 Git 或无本次改动时跳过。

## 触发时机

- 用户要记录研究或开发过程、整理物理/代码任务笔记、沉淀证据索引、临时结论、会议/讨论纪要
  或交接摘要。
- 场景包括实验记录、推导笔记、调试过程、测试总结、讨论摘要、日常工作纪要和跨会话交接包。
- 与其他技能配合：恢复中断现场先用 `go-on`；只想压缩成短交接包或行动项先用 `follow-up`；
  需要正式科研汇报或幻灯片先用 `report`；需要仓库全景、结构和关系分析先用 `analy`；
  需要穷尽核心算法、物理图像或代码-物理映射先用 `pure`。
- 不使用本技能：恢复中断现场本身、正式汇报、仓库全景分析、核心细节穷尽或实现/调试本身。

## 工作流程

### Step 1. 确认主题与范围

1. 明确主题、受众、时间范围、交接对象，以及这次记录要偏过程、偏结论还是偏接续。
2. 缺项一次问全；如果用户其实要的是 `go-on`、`follow-up`、`report`、`analy` 或 `pure`，先分流。

### Step 2. 写下过程记录

1. 先按下面骨架起笔，保留事实和顺序，不急着润色：

```markdown
# <主题> 过程笔记
## 任务与范围
## 过程记录
## 证据索引
## 临时结论
## 未验证项与风险
## 接续摘要
```

2. 过程记录优先写“做了什么、看到什么、改了什么”，不要先写判断。
3. 物理任务保留关键推导链、量纲/极限检查和假设；代码任务保留命令、输入、输出、失败现象和修正依据。

### Step 3. 绑定证据并分级结论

1. 每条关键判断都绑定真实来源，优先写文件:行号、命令、输出文件或讨论要点。
2. 证据索引建议一行一条：

```text
id | claim | source | status | note
```

3. `status` 只用 `确证` / `推断` / `未验证`，不要把猜测写成事实。

### Step 4. 生成接续摘要

1. 结尾保留一个可直接交给后续 agent 的摘要，至少包含当前状态、已确认事实、待验证项、下一步动作、相关文件或命令。
2. 摘要要短，足够让后续 agent 立刻继续，不要扩写成正式报告。

### Step 5. 增量更新与落盘

1. 同主题同日优先追加更新，保留时间线，不覆盖已有记录。
2. 默认产物写到 `docs/notes/<主题slug>_<YYYYMMDD>.md`；同日同题重复记录时追加 `_2`、`_3`。
3. 只保留对后续决策有用的信息，不把笔记写成成稿。

## 错误处理

| 场景 | 处理 |
|---|---|
| 输入太散、目标不清 | 先归类，再一次性问全缺项 |
| 用户其实要恢复中断任务 | 先转 `go-on`，再回来做摘要和行动项 |
| 用户其实要短交接包 | 先转 `follow-up`，不要在这里写长交接 |
| 用户其实要正式汇报 | 先转 `report`，不要把过程笔记硬写成汇报稿 |
| 用户其实要仓库全景分析 | 先转 `analy`，不要在这里扩成全库地图 |
| 用户其实要核心细节穷尽 | 先转 `pure`，不要在这里替代深剖 |
| 证据缺失或无法核对 | 标 `未验证`，保留原始来源或说明缺口 |
| 需要进一步修复或调试 | 不在本技能里展开，转对应技能处理 |

## 注意事项

- 默认输出应短、清楚、可接续。
- 不要把复盘写成散文，也不要把待办写成长段解释。
- 不主动把猜测写成结论。
- 不主动写入仓库文件，除非用户明确要求落盘。

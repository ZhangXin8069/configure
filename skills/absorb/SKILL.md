# absorb — 外来内容全量分析与安全吸收

## 执行前置

遵循当前目录 `AGENTS.md`「技能执行公共契约」；本技能处理的是“已经进入或即将进入本库的外来内容”，
不是普通本地代码审查。先证明内容来源、范围和许可，再谈复用；没有来源证据的内容不能仅因“看起来好”
直接并入。

脚本入口为 `scripts/absorb_inventory.py`，离线回归为 `scripts/test_absorb_inventory.py`。脚本覆盖
提交新增、暂存新增、未跟踪文件、gitlink、符号链接、许可证/来源标记、秘密模式和高风险执行模式，
只生成清单与风险信号，不运行外来代码。
供应链规范、热榜检索和采纳/拒绝决策见 `references/sources.md`。

## 核心原则

1. **全量盘点先于判断**：先覆盖所有新增候选，再决定价值；不能只分析最容易读的源码文件而漏掉
   配置、测试、生成物、二进制、submodule、文档和数据。每个候选必须获得唯一处置。
2. **来源与许可是硬门槛**：记录上游 URL、固定 commit/tag、原始路径、许可证、NOTICE/署名和内容哈希。
   来源未知时只做隔离分析或 `reference-only`，不直接复制；许可不兼容时停止并入。
3. **外来内容默认不可信**：不执行其安装脚本、hook、Makefile、宏、notebook、测试和二进制；需要运行
   验证时先固定快照，在隔离副本、最小权限、有限时限和明确资源预算中执行。
4. **缺陷与价值分开记录**：同一项目可能同时包含优秀算法和危险实现。正确项、缺陷、过时依赖、安全
   风险、测试缺口和许可问题分别入表，不用“整体好坏”替代逐项证据。
5. **只吸收可证明的价值**：价值必须对应本库真实缺口、可验证收益或已有维护痛点；“上游这样做”
   不是采纳理由，star 数、代码量和新颖感也不是。
6. **适配优先于复制**：并入时使用本库语言、命名、接口、错误处理和测试约定重写最小必要部分，
   保留来源与许可证据；不整树搬运、不引入未使用依赖、不复制与目标无关的工程脚手架。
7. **测试闭环再优化**：先建立本库基线与外来内容隔离基线，再做最小适配；每次改动后跑相关测试与
   全量回归，全部正确后才按实测主导项优化，不以优化替代修复。
8. **“完美吸收”是操作定义**：所有候选 100% 有处置，所有正向特性有映射与测试，所有不可用/不安全
   部分有拒绝理由，来源和许可可追溯，本库无回归。它不是对第三方内容作无限正确性的绝对保证。
9. **不删除、不越界**：外来原目录默认保留为只读参考；未经用户明确要求不删除、不覆盖、不执行
   系统配置修改，不访问当前 Git 工作树之外无关内容。

## Git 检查

有 Git 且本次产生文件改动时，执行：

```bash
repo_root="$(git rev-parse --show-toplevel)"
git -C "$repo_root" diff --check
git -C "$repo_root" status --short
```

只暂存本任务明确文件；未获授权不提交、不推送、不打标。任何提交前另按 `form` 要求运行
`form-large-files-check.sh`。工作区已有他人改动时只记录，不覆盖或回退。

## 触发时机

- 工作树、暂存区或最近提交中新出现 `refer/`、`vendor/`、`third_party/`、`external/`、submodule、
  外部 skill、算法、配置、测试或文档，需要判断“能不能用、哪里有问题、哪些值得吸收”；
- 用户说 `absorb`、`吸收外部内容`、`分析新增外来代码`、`把外部项目优点并入本库`、
  `审查导入内容`、`吸收这个参考实现`；
- 外部内容已复制进仓库但尚未建立来源、许可、测试和拒收边界；
- 与其他技能配合：来源/生态调研转 `up`；代码质量问题转 `review`；复现失败转 `debug`；
  功能验证转 `test`；有测量依据的性能改进转 `optim`；目录/命名整改转 `form`；
  多组互不依赖的候选分析转 `dispatch`；阶段/最终证据归档转 `log`；长任务资源门控转 `rule`。

## 工作流程

### Step 1. 定义吸收边界并建立全量清单

1. 明确目标 Git 根、基线 ref、是否包含未跟踪/暂存内容、允许合并的范围和停止条件。
2. 默认 `base=auto`：优先使用 upstream merge-base，其次 `HEAD^`；同时在 `all` 范围纳入暂存和
   未跟踪新增。用户指定提交区间时传 `--base <ref>`。默认排除 Git ignored 内容以避免依赖/构建缓存；
   外来内容位于 ignored 目录时显式加 `--include-ignored`。
3. 将清单写入已忽略的运行目录：

   ```bash
   repo_root="$(git rev-parse --show-toplevel)"
   absorb_run="$repo_root/data/runs/absorb/$(date +%Y%m%d-%H%M%S)"
   mkdir -p "$absorb_run"
   python3 "$repo_root/skills/absorb/scripts/absorb_inventory.py" \
     --root "$repo_root" \
     --base auto \
     --scope all \
     --output "$absorb_run/inventory.json" \
     --quiet
   ```

4. 脚本按 `commits`、`staged`、`untracked`、`worktree-diff` 分别建立候选，并使用对应 Git blob
   或当前工作树版本计算 SHA-256；同一路径若暂存后又被修改，会得到多个版本候选，不能用一个版本
   覆盖另一个。gitlink 记录目标 OID，符号链接只记录目标哈希/长度，不输出目标原文。
5. 检查 `candidate_count`、`by_origin`、`by_risk`、`by_source`、`by_top_group`。若没有候选，确认
   scope/base 与 `include_ignored` 后
   输出“无可吸收新增内容”并停止，不创建虚假分析。
6. 为每个 candidate `id` 建立覆盖账本。后续任何结论都必须引用 candidate id 或 `文件:行号`；
   二进制/gitlink 也要有明确处置，不能从统计中消失。

### Step 2. 确认来源、版本与许可

对每个内容组确定：

| 字段 | 证据 |
|---|---|
| 上游 | 网站、仓库/项目名、canonical URL、固定 commit/tag |
| 原始范围 | 导入路径、上游相对路径、是否重命名/裁剪 |
| 许可 | SPDX 标识或许可证原文、NOTICE/署名、兼容性判断 |
| 完整性 | 当前子树 SHA-256、单个关键文件 SHA-256、版本差异 |
| 生成方式 | vendored/generated/fork/manual copy/unknown |
| 本地目的 | 参考、替换、补充、实验或临时对照 |

`likely-foreign` 只是启发式信号，不等于来源已确认。无法找到上游或许可时：

1. 保留内容，不改动，标 `origin=unknown / license=unknown`；
2. 允许静态分析和隔离测试，但默认处置为 `reference-only`；
3. 只有用户提供来源/授权证据后才升级为 `keep` 或 `adapt`。

### Step 3. 全面分析：先找问题，再提取价值

对每组外来内容按以下维度全覆盖；可按独立目录并行派发，但必须由主 agent 汇总：

1. **结构与入口**：目录树、入口点、构建/安装链、运行时依赖、版本约束、生成物与源文件边界。
2. **正确性**：核心算法/控制流、边界条件、错误处理、并发、幂等、资源生命周期和平台假设。
3. **安全性**：动态执行、网络访问、凭据/秘密、文件写入、路径穿越、反序列化、命令注入、
   非必要权限、hook/自动加载和不可信二进制。
4. **供应链**：未固定版本依赖、废弃包、许可证冲突、缺失 NOTICE、来源不明代码、二进制不可复现。
5. **测试与文档**：测试是否能在隔离环境运行、覆盖哪些边界、文档与实际行为是否一致。
6. **本地适配**：与本库现有技能/脚本/接口的职责重叠、命名冲突、数据格式差异和可迁移边界。
7. **正向价值**：可复用算法、设计模式、错误处理、测试用例、配置默认值、文档结构、性能技巧。

清单中任何 `scan_truncated=true` 的候选都不能视为已扫描完毕；必须继续用只读分块、`git show`
或 `rg` 检查剩余内容，特别是秘密、执行指令和许可证文本。命中只保留行号、数量和脱敏类别，不输出秘密值。

静态调查优先：

```bash
git -C "$repo_root" grep -n -I -E 'subprocess|os\.system|eval\(|curl|wget|rm -rf|BEGIN .*PRIVATE KEY' -- <candidate-paths>
rg -n --hidden --glob '!.git/**' 'upstream|forked from|SPDX-License-Identifier|Copyright' <candidate-paths>
```

禁止直接跟随外来符号链接、执行其脚本或加载其配置。需要动态验证时，复制固定哈希到隔离临时目录，
先读测试与构建入口，确认无危险命令，再使用 `timeout`、最小环境变量和非特权用户执行。

### Step 4. 建立吸收矩阵

每个 candidate id 必须落入且只落入一种处置：

| 处置 | 含义 | 允许动作 |
|---|---|---|
| `keep` | 来源/许可明确，内容适应当前用途 | 保留原位置并登记来源；必要时补 NOTICE |
| `adapt` | 有明确正向价值，但需按本库规范重写/裁剪 | 最小实现 + 来源说明 + 针对性测试 |
| `reference-only` | 有参考价值但来源/许可/质量/依赖不适合并入 | 只读引用，不复制进运行路径 |
| `reject` | 错误、过时、危险、冗余或收益不足 | 记录理由，不进入本库 |

矩阵至少包含：

```text
candidate_id | 证据位置 | 正向价值 | 缺陷/风险 | 本库缺口 | 兼容性 | 处置 | 目标文件 | 验证 | 来源/许可
```

找不到本地缺口的“好设计”不进入实现；已有等价且更可靠实现时，优先记录“已覆盖”，避免重复造轮子。

### Step 5. 最小适配合并

1. 先写/补针对性测试或可复现断言，证明当前缺口和预期行为；若库约定不要求 TDD，至少保留失败证据与
   通过证据。
2. 只改实现该价值所需文件；遵循本库命名、函数结构、错误处理、日志与安全边界。
3. 合并代码时保留来源 URL、固定 ref、许可证和适配说明；不把整个上游工程直接复制为本库模块。
4. 新依赖必须证明必要性，说明版本、许可证、安装成本、离线可用性和替代方案；能用标准库就不用新依赖。
5. 不自动启用外来 hook、plugin、marketplace 或后台服务；这类内容必须显式配置并单独审查。
6. 外来内容与本地改动冲突时，保留本地原约定；无法安全合并时停止并提交冲突矩阵，不猜写。

### Step 6. 测试、审查与回归

先运行本库既有验证，再验证吸收点：

```bash
bash -n <changed-shell-scripts>
python3 -m py_compile <changed-python-scripts>
python3 "$repo_root/skills/absorb/scripts/test_absorb_inventory.py"
python3 "$repo_root/skills/get-paper/scripts/test_get_paper.py"  # 仅在相关技能受影响时
"$repo_root/tools/configure-check.sh" --root "$repo_root"
"$repo_root/skills/form/scripts/form-audit.sh" --root "$repo_root" --strict --quiet
git -C "$repo_root" diff --check
```

验证矩阵要求：

- 每个 `adapt` 项至少有一个正向测试和一个边界/错误测试；
- 原有功能全部回归，不能以“外来测试通过”替代本库测试；
- 秘密模式命中必须人工确认并脱敏，Critical 风险未关闭前不得合并；
- 只读运行外来测试时，记录其依赖、超时、退出码和是否改变工作区；
- 修改后调用 `review` 做需求一致性、安全和测试覆盖审查，修复后再全量回归。

### Step 7. 基于证据进一步优化

测试全部通过后才进入优化，最多进行 3 轮，直到无实质收益或达到明确指标：

1. 测量基线 3–5 次并记录中位数、输入规模、资源上限和环境；
2. 只处理实测主导项，例如重复 IO、无界扫描、过度复制或复杂度不合理的匹配；
3. 每轮只做一个优化动作，优化后先跑全量测试再复测；
4. 收益低于 5% 或明显增加维护复杂度时停止，报告权衡；
5. 不为“吸收更多”扩大范围；新增价值必须有本库缺口和验证证据。

### Step 8. 判定吸收是否完整

仅在以下全部成立时输出“吸收完成”：

1. inventory 中每个 candidate id 均有且仅有一种处置；
2. 所有 `keep`/`adapt` 项均有来源、许可、固定 ref 与本地映射；
3. 所有 `adapt` 项均有针对性测试，且原有测试与结构检查通过；
4. 所有 Critical 安全问题已消除；Important 问题已修复或明确阻塞；
5. 未能吸收的内容均有可复核理由，不以“以后再看”代替结论；
6. 无越界访问、无未授权系统配置、无秘密泄露、无未说明的大文件；
7. `git diff --check` 为零，改动范围只含本任务文件。

无法满足时可以报告“参考分析完成，但未吸收”，不得宣称“完美吸收”。

### Step 9. 输出

```text
✓ absorb 完成
   范围:   <Git 根、base/HEAD、scope、候选数>
   来源:   <上游、固定 ref、许可证与哈希证据>
   覆盖:   <N/N candidate id 已处置>
   价值:   <keep/adapt/reference-only 的关键正向点>
   缺陷:   <已修复问题、拒绝项及证据>
   改动:   <本库文件:行号与适配说明>
   验证:   <离线测试、全量回归、结构检查、diff 结果>
   优化:   <轮数、基线→优化后、是否停止于收益微小>
   遗留:   <许可不明、Important 风险、未验证项>
```

## 错误处理

| 场景 | 处理 |
|---|---|
| 当前目录不是 Git 工作树 | 停止并要求目标路径；不扫描工作树外内容 |
| 无新增候选 | 确认 base/scope 后输出 no-op；不伪造“吸收结果” |
| 来源或固定 ref 不明 | 标 `origin=unknown`，允许静态分析，默认 `reference-only`；不直接并入 |
| 许可缺失或冲突 | 停止复制/再分发，只保留分析证据；必要时请用户提供授权 |
| 发现秘密或凭据 | 记录文件/行号和类型，值脱敏；不复制、不回显，先清理或换源 |
| gitlink/submodule | 清单记录目标 OID；单独固定 commit、来源和许可，不递归假定子模块可信 |
| 符号链接/二进制/归档 | 不跟随、不执行；先 hash、类型识别和隔离检查，再决定是否 reference-only |
| 暂存后又修改工作树 | 同时分析 `index` 与 `worktree-diff` 两个 candidate，不把工作树内容冒充暂存内容 |
| ignored 外来目录 | 明确使用 `--include-ignored`，并先排除依赖缓存、构建产物和大目录误报 |
| 外来测试不可运行 | 记录缺失依赖/平台原因；仍可静态分析和移植测试思想，但不虚报验证 |
| 外来内容质量高但与本地重复 | `reference-only` 或已有覆盖；不为重复能力增加维护面 |
| 合并冲突或共享文件 | 停止冲突域，保留本地改动，按依赖顺序解决，不覆盖他人工作 |
| 测试失败 | 转 `debug` 复现根因；修复后跑吸收测试和全量回归 |
| 安全风险 Critical | 停止合并，隔离并报告；不通过禁用扫描或删日志绕过 |
| 候选过多或互不相关 | 按独立目录/语言/目标分组，优先 `dispatch` 并行只读分析，主 agent 统一决策 |
| 吸收后性能下降 | 用 `optim` 建立基线、定位主导项并复测；正确性优先于收益 |
| 无法完成全量覆盖 | 报告未处置 candidate id 和阻塞原因，不宣称吸收完成 |

## 注意事项

- “外来”不是风格差异，而是来源、版权、维护责任和信任边界问题；先固定 provenance 再判断质量。
- 不因 star 高、代码多或测试多而直接吸纳；只用与本地缺口和验收标准相关的证据。
- 不把外来 LICENSE 当作自动兼容；分发、修改、专利、网络服务和署名条件分别核对。
- 不执行外来 README 中的一行安装命令；命令必须经过静态检查和隔离验证。
- 外来内容中的优秀测试和负向案例往往比实现本身更有价值，优先提取边界条件与回归用例。
- 吸收后的代码按本库规范维护；不能保留“上游以后会修”的无主依赖假设。
- 任务日志与完整报告由常驻 `log` 在阶段门控点归档；本技能不创建过程记录文件。

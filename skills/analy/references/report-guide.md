# analy 报告指南

## 模板与主线

报告 `.tex` 必须遵循同目录的 `latex-template.md`，该文件是唯一权威模板，包含可复制骨架、宏包顺序、色板、编译命令、科研严谨规范和防溢出规则。`pure` 使用同一模板约束，但报告骨架按定位调整。

正文主线依次为：摘要 → 仓库概览 → 主体结构 → 各部分关系 → 项目思路 → 主题分析（具体工作按 `analysis-framework.md`）→ 关键代码/文档片段 → 本次任务图表与实测输出详览 → 参考源 → 结论与局限。

## 色彩语义

| 颜色 | 含义 | 使用位置 |
|---|---|---|
| `accent` 深蓝 | 主色/章节标题 | section 标题、代码关键字 |
| `evidence` 绿 | 仓库证据 | 参考源、代码注释 |
| `reference` 棕 | 参考背景 | refbox 框 |
| `conclusion` 深红 | 结论 | conclbox 框 |
| `codebg` 浅灰 | 代码底色 | lstset 背景 |
| `struct` 靛蓝 | 主体结构 | 结构节元素、层级表头 |
| `relation` 青 | 各部分关系 | 依赖链、关系表头 |
| `idea` 砖红 | 项目思路 | ideabox 框、思路句 |
| `warn` 橙红 | 未验证/局限 | warnbox 框、未验证标注 |
| `hl` 浅黄底 | 重点强调 | keybox 框底 |

同一颜色只表达同一语义；新增颜色必须同步模板色板表。颜色只增强可读性，不承载唯一信息。

## 防溢出底线

交付前 `grep -c Overfull` 与 `grep -c "Float too large"` 必须均为 0。长代码每段不超过 40 行，长表使用 `xltabular` 跨页，图片使用 `width=0.9\textwidth,height=0.6\textheight,keepaspectratio`，并按模板使用 `\emergencystretch`、microtype、breakable 框和分行公式。

## 交付检查

- [ ] 主题已解析为任务定义并在终端摘要中说明；含糊主题已一次性确认。
- [ ] 全库索引、git 元信息和覆盖表闭合；目录/类型/git 历史/入口引用链均已检查。
- [ ] 主体结构、各部分关系、项目思路三视角齐全；参考知识库已检索并说明未引入项。
- [ ] 每个结论有经核实的 `文件:行号`，并标注确证/推断/未验证；代码片段用 `\lstinputlisting` 直引且每段 ≤40 行。
- [ ] 多资料有联系与层次；代码主题有对象映射；具体工作主题按 15 步框架完整展开，第 9 步实证。
- [ ] 图表和实测输出清单闭合并逐项解读；特殊字符已转义；PDF 非空且 `Overfull`/`Float too large` 均为 0。
- [ ] 总结覆盖主题、覆盖范围、参考、证据、产物、结论与局限。

## 示例

输入 `{~analy 环境加载链 env.sh 的模块构成}` 时，任务定义为“分析主题：环境加载链 env.sh 的模块构成”，报告应展示 `env.sh` 到 `lib/` 的依赖链并用 `\lstinputlisting` 直引代码。

输入 `{$ 梳理 lib/ 下各版本化配置目录的关系与用途}` 时，报告应给出目录/版本/职责表和 `env.sh → lib/_git_aliases.sh → lib/name-v{YYYYMMDD}/` 依赖链。

输入 `{~analy 格点 QCD 谱计算代码对应哪些物理量}` 时，报告应给出代码符号、对象概念和物理含义的映射，并直引相关原文件。

# phys-model — 物理建模与数值落地技能

## 执行前置

遵循当前目录 `AGENTS.md`「技能执行公共契约」；仅按需读取技能正文与 reference。

先把物理问题压成可计算对象，再决定方程、离散化和验证。若任务焦点其实是仓库结构，先转 `analy`；若要穷尽既有核心物理/代码细节，先转 `pure`；若模型已经成立、重点是跑验证，先转 `test`。

## 核心原则

1. **先定义物理对象，再谈求解**：先写清自由度、观测量、几何、初值/边界条件、控制参数和目标输出，避免在未定义对象时直接选方程。
2. **先做对称性、守恒和量纲筛选**：允许哪些项、禁止哪些项、哪些小量可以忽略，先由物理约束决定，再进入数值实现。
3. **连续模型、离散格式、求解器分层**：控制方程是什么、网格/时间步怎么选、迭代器怎么收敛，是三层不同决策，不能混成一层写。
4. **极限与退化校验是硬门槛**：连续极限、零耦合、小参数、大盒子、静态极限、对称退化都要能回到已知答案或合理边界。
5. **误差预算要和物理量绑定**：稳定性、截断误差、收敛判据、守恒漂移都要对应到具体物理量或无量纲指标。
6. **最小闭环优先**：先做能跑通、能验证、能解释的最小模型，再按证据扩展复杂度，不先堆高阶机制。
7. **实现要服务于模型**：代码结构应忠实反映模型结构，便于把假设、方程、离散项和验证项逐一追溯。
8. **边界要交给更专门的技能**：仓库地图和入口链交给 `analy`，既有核心细节交给 `pure`，系统化回归交给 `test`，性能瓶颈交给 `optim`。

## 触发时机

**使用本技能**：

- 用户说“帮我建模”“第一性原理推导”“把这个物理问题数值化”“做离散化”“写模拟代码”
- 用户要求量纲检查、对称性检查、守恒检查、稳定性分析、收敛性分析、极限检验、退化检验
- 用户要把连续方程落成有限差分、有限体积、有限元、谱方法、粒子法或混合数值方案
- 用户要把模型实现成可运行代码，并验证数值结果是否可信
- 与其他技能配合：多文件/多子模型并行调查用 `dispatch`；实现前先写计划用 `plan`；落地实现和归档用 `make`；数值验证用 `test`；结果不稳或方程不闭合时用 `debug`；性能不足时用 `optim`

**不使用本技能**（转用对应技能）：

| 场景 | 改用技能 |
|---|---|
| 仓库结构、入口、依赖、文档关系 | `analy` |
| 既有核心算法/物理对象的穷尽剖析 | `pure` |
| 纯数值回归、跑测试、验证已有实现 | `test` |
| 先把实现任务拆解成可执行计划 | `plan` |
| 明显的性能/启动/资源问题 | `optim` |
| 已经出现异常输出、发散或不守恒 | `debug` |

## 工作流程

### Step 1. 锁定物理问题

1. 明确系统是什么：对象、尺度、边界、输入、输出、希望保留的物理效应；
2. 写出验收标准：要证明什么、允许多大误差、需要哪些对照或基线；
3. 若缺少关键约束，先一次性把缺项问全，不直接猜边界或参数。

### Step 2. 建立连续模型

1. 从守恒律、变分原理、对称性或已知本构关系出发写方程；
2. 标记每个假设：近似、忽略项、线性化、尺度分离、闭合条件；
3. 为每个方程写清量纲、守恒量和适用范围。

### Step 3. 做物理筛查

1. 检查量纲是否闭合；
2. 检查对称性、守恒律和边界条件是否一致；
3. 做极限和退化校验：无耦合、连续极限、静态极限、长波/短波极限、参数趋零或趋无穷。

### Step 4. 选离散化与数值方案

1. 选空间离散和时间推进：有限差分、有限体积、有限元、谱方法或粒子法；
2. 说明稳定性条件、网格/步长、边界闭合和求解器类型；
3. 把误差来源拆开：截断误差、迭代误差、舍入误差、建模误差。

### Step 5. 落到最小实现

1. 把模型、网格、求解器和诊断分开，不把画图/IO 混进核心方程；
2. 先实现最小可运行路径，再扩展多物理、多参数或高阶格式；
3. 在仓库中改代码时，保留可追溯证据：文件、接口、行号和测试输出。

### Step 6. 验证闭环

1. 对照解析解、简化极限、制造解或文献基准；
2. 做网格/步长收敛、参数敏感性和守恒漂移检查；
3. 结果若不对，先回到模型假设和离散格式，不先盲目调容差。

## 错误处理

| 场景 | 处理 |
|---|---|
| 初值/边界条件缺失 | 停下并向用户补问，不替用户猜物理设定 |
| 量纲不闭合或守恒被破坏 | 回到连续方程和离散项逐项重写，先修模型再修代码 |
| 数值格式不稳定 | 检查 CFL/步长/网格/边界闭合，必要时换格式而不是只缩小步长 |
| 结果和极限不一致 | 先查假设与退化路径，再查实现；不要把偏差直接归因于“数值误差” |
| 没有解析基准 | 用制造解、对称退化、上下界或保守量作为替代验证 |
| 模型已经成立但实现发散 | 交给 `debug`；若主要矛盾是性能，交给 `optim` |

## 注意事项

- 这个技能解决的是“物理问题怎么变成可算模型”，不是仓库全景分析，也不是核心细节穷尽剖析。
- 当任务需要先看项目地图，再决定从哪里下手时，先用 `analy`。
- 当任务已经有明确模型，只需要把最强细节挖到底时，先用 `pure`。
- 当任务的目标是数值正确性和回归稳定性时，和 `test` 搭配使用。

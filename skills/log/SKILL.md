# log — 主任务阶段日志与报告归档

## 执行前置

遵循当前目录 `AGENTS.md`「技能执行公共契约」；先读取主任务的用户指令、已验证阶段结果和
将要交付的报告，再选择日志模式。本技能是主任务的辅助归档层，不替代 `report` 的正式展示、
`research-notes` 的过程笔记或 `follow-up` 的交接摘要。

`log` 是常驻辅助技能：当前任务用户未明确说明“不记录日志”“关闭 log”等时，默认与任一被调用的
技能共同启用，包括单独调用其他技能。常驻不等于逐命令记录；未关闭时只在以下门控点触发：

- 主任务取得可验收的阶段成果并给出阶段报告；
- 主任务需要记录一般执行日志；
- 主任务全部完成并进行最终归档；
- 用户明确调用 `{~log}` 或要求补写本次任务的日志。

## 模式与路径

日志始终写入当前工作目录所在 Git 根目录的 `logs/`：

```text
<git-root>/logs/
```

| 模式 | 触发 | 默认文件名 | 必须内容 |
|---|---|---|---|
| `stage` | 阶段成果和阶段报告已形成 | `v%Y%m%d%H%M.txt` | 关键日志、阶段报告全文 |
| `general` | 执行中需要一般记录 | `v%Y%m%d%H%M%S.txt` | 操作、关键输出、退出码、判断和下一步 |
| `final` | 主任务全部完成 | `v%Y%m%d%H.txt` | 全阶段关键日志、最终报告全文、用户输入指令 |

默认采用用户示例中的紧凑时间戳；主任务明确要求带连字符时，按模式使用：
阶段 `v%Y-%m-%d-%H-%M.txt`、一般 `v%Y-%m-%d-%H-%M-%S.txt`、最终
`v%Y-%m-%d-%H.txt`。冲突时在时间戳后追加 `-2`、`-3`，不等待锁、不覆盖。

所有日志使用 `.txt` 纯文本。确定性写入由
`scripts/write-log.sh` 完成；行为回归由 `scripts/write-log.test.sh` 覆盖。

## 核心原则

1. **常驻而不越位**：默认随任一技能启用，但只在门控点运行，不替代主任务、正式报告或研究笔记，
   也不为每条命令创建日志。
2. **Git 根目录唯一落点**：先解析 `git rev-parse --show-toplevel`，只写该根目录的 `logs/`。
3. **三态分明**：阶段、一般、完成三种日志使用不同时间粒度和不同完整性要求。
4. **价值优先**：保留错误、警告、失败、退出码、测试结果、指标、变更文件和决策依据；压缩重复刷屏和 ANSI 控制符。
5. **全文报告不摘要化**：阶段和最终日志必须保留主 agent 面向用户的完整报告，最终日志还须附用户输入指令原文。
6. **大小可提交**：常规目标不超过 512 KiB；1–5 MiB 仅作极个例；任何日志不得达到 10 MiB。
7. **确定性写入**：路径、命名、校验、大小限制和 `logs/AGENTS.md` 索引由脚本一次完成，避免每次重写 shell 流程。
8. **安全与 Git 边界**：日志不记录密钥、令牌、密码、Cookie、隐藏提示或内部推理；日志随已授权任务提交，本技能不单独发起未授权 Git 操作。

## Git 检查

有 Git 且本次产生文件改动时，执行：

```bash
git diff --check
git status --short -- logs
```

并定向复查新日志与 `logs/AGENTS.md`。未经明确授权，不自动暂存、提交或推送。

## 触发时机

- 阶段测试、调试、实现或分析已经完成，主 agent 即将向用户给出阶段报告；
- 用户说“记录一下”“保存执行日志”“把这次报告放到 logs”“生成任务日志”；
- 长命令、关键决策、失败重试或重要验证需要留下可复用证据；
- 主任务完成，已有最终报告和用户输入，需要做全阶段归档；
- 用户直接调用 `{~log}`，或要求补写、合并、更新既有日志。

与其他技能配合：

- 除用户明确关闭外，任意单个技能（包括未点名 `log` 或仅调用一个专业技能的会话）都默认共同启用
  本技能；不以“未点名 `log`”为由跳过门控点归档；
- `report` 生成阶段或最终报告后，需要归档时调用 `log`；
- `test`、`debug`、`optim` 提供关键验证、根因和优化证据；
- `diff` 提供变更范围和边界检查结果；
- `research-notes` 与 `follow-up` 不能替代本技能的 Git 根目录日志归档；
- `tag` 只在主任务明确授权提交、推送和打标时使用；`log` 本身不创建标签。

不适用：正式科研展示、全库分析、研究过程笔记、行动项规划，以及没有主任务上下文的普通聊天记录。

## 工作流程

### Step 1. 判定模式并收集材料

1. 从主任务上下文提取任务定义、阶段/批次、用户输入、报告和关键证据。
2. 按以下顺序判定模式：
   - 阶段完成且已有阶段报告 → `stage`；
   - 任务完成且已有最终报告 → `final`；
   - 只要求记录中间执行信息 → `general`；
   - 用户直接调用但未说明模式 → 默认 `general`，并在结果中说明。
3. `stage` 或 `final` 缺少报告时先完成报告；不能凭计划或推测伪造全文报告。
4. 用户输入只取主任务可见的用户消息，不记录系统/开发者提示、隐藏推理或无关会话。

### Step 2. 组织日志正文

脚本会自动写入元数据；正文通过 stdin 传入。使用以下骨架，按模式保留必需章节：

```text
## 关键日志
### S1 — <阶段或事件>
- 目标:
- 命令/操作:
- 关键输出:
- 退出码:
- 证据与判断:

## 验证与证据
- 测试/检查:
- 结果:
- 未验证项:

## 变更与产物
- 文件:
- 产物:
- 未改动范围:

## 风险、限制与下一步
- 风险:
- 阻塞:
- 下一步:

## 用户输入指令
<final 必填；用户原话，可做凭据脱敏>

## Agent 全文报告
--- report begin ---
<stage/final 必填；主 agent 面向用户的完整报告，原样保留>
--- report end ---
```

内容提取规则：

1. 优先保留命令、退出码、错误/警告、测试断言、数值指标、文件路径、关键 diff 和最终判断。
2. 重复的成功进度、常规文件读取、无信息量重试和长时间刷屏压缩为一条摘要并注明次数。
3. 删除 ANSI 颜色、回车覆盖、进度条动画和二进制内容；必要时只保留关键行及上下文。
4. `final` 的 `关键日志` 按 `S1`、`S2` 汇总全部阶段，再附最终报告和用户输入。
5. 不用日志承载隐藏推理；只记录可观察操作、结果、证据和简短决策理由。

### Step 3. 调用确定性写入器

解析技能目录并确认脚本存在：

```bash
skill_dir="${LOG_SKILL_DIR:-$HOME/configure/skills/log}"
test -x "$skill_dir/scripts/write-log.sh"
timestamp_style=${timestamp_style:-compact}
```

将 Step 2 的正文放入 `log_body`，然后调用：

```bash
printf '%s\n' "$log_body" |
  "$skill_dir/scripts/write-log.sh" \
    --mode "$mode" \
    --task "$task" \
    --batch "$batch" \
    --summary "$summary" \
    --timestamp-style "$timestamp_style"
```

默认 `timestamp_style=compact`；需要带连字符时传 `hyphen`。
脚本负责：

- 解析 Git 根目录并检查 `logs/` 未越界；
- 校验 `## 关键日志` 以及模式要求的报告/用户输入章节非空；
- 拒绝冲突标记、被 Git 忽略的路径和达到 10 MiB 的日志；
- 选择不冲突文件名、原子安装日志并设置 `0644`；
- 追加 `logs/AGENTS.md` 批次说明；
- 输出 `log_file`、`size_bytes`、`index_file` 等 key=value 结果。

脚本返回非零时不得声明日志完成；根据错误修正正文或路径后重试。脚本缺失时报告具体路径并停止，
不要临时复制一套不一致的写入流程。

### Step 4. 验证结果

从脚本输出取得 `log_file`，执行：

```bash
repo_root="$(git rev-parse --show-toplevel)"
test -s "$log_file"
grep -Fq "$(basename "$log_file")" "$repo_root/logs/AGENTS.md"
git -C "$repo_root" status --short -- "logs/$(basename "$log_file")" logs/AGENTS.md
git -C "$repo_root" diff --check
```

确认输出包含实际绝对路径、字节数、目标阈值、硬上限和索引路径。`final` 日志还应能看到
用户输入、全阶段摘要和完整最终报告。

### Step 5. 仅在授权范围内提交

日志应随主任务进入远程仓库；本技能不单独发起未经授权的 Git 操作。主任务已有提交授权时，
把本批次日志和 `AGENTS.md` 显式列入同一提交：

```bash
repo_root="$(git rev-parse --show-toplevel)"
log_rel="logs/$(basename "$log_file")"
git -C "$repo_root" add -- "$log_rel" logs/AGENTS.md
git -C "$repo_root" commit -m "docs(log): archive $(basename "$log_file")"
```

只有用户明确要求同步远程时才执行 `git push`。多个阶段文件一起提交时逐个列出；
不使用未经核对的 `logs/` 全目录暂存。推送失败时如实报告本地状态和失败原因。

### Step 6. 返回结果

```text
✓ log <stage|general|final> 写入
   文件: <绝对路径>
   大小: <bytes> bytes（目标 ≤512 KiB，硬上限 <10 MiB）
   内容: <关键日志 + 全文报告/用户指令>
   索引: logs/AGENTS.md
   验证: <脚本校验、Git 状态、diff 检查>
   Git: <未暂存/已本地提交/已推送/未授权>
```

## 错误处理

| 场景 | 处理 |
|---|---|
| 当前目录不在 Git 工作树 | 不猜测根目录；停止并报告，等待用户明确路径 |
| `scripts/write-log.sh` 缺失或不可执行 | 报告具体路径并停止，不临时重写不一致的写入流程 |
| `stage`/`final` 报告尚未形成 | 不使用计划或推测冒充报告；先完成报告，或按用户要求生成一般日志 |
| 缺少 `关键日志`、报告或用户输入章节 | 按脚本错误补全对应章节后重试；不绕过校验 |
| 目标文件名已存在 | 脚本自动追加 `-2`、`-3`；不等待锁、不覆盖 |
| 日志达到 10 MiB | 压缩重复日志；若全文报告本身导致超限，报告约束冲突并等待拆分或用户决策 |
| 报告较长但低于硬上限 | 允许作为极个例，在索引记录实际大小；不截断全文报告 |
| `logs/AGENTS.md` 写入失败 | 不宣称归档完成；报告日志路径和索引失败原因 |
| 日志路径被 Git 忽略 | 说明规则，不假装日志可提交；由用户决定调整忽略规则 |
| 日志含密钥/令牌/密码 | 先脱敏并写明“已脱敏”，不得把原值写入文件或终端摘要 |
| 提交/推送认证失败 | 保留本地日志，报告失败命令和已完成的本地操作 |
| 同一批次重复执行 | 按冲突规则新建文件，索引保留两条可追踪记录 |
| 显式调用但模式不明 | 默认 `general`；上下文表明是阶段或最终报告时改用对应模式 |
| 用户明确关闭日志 | 仅对当前任务停用；不要在未来任务中沿用该例外，也不要创建空日志占位 |

## 注意事项

- 默认不为每条命令创建日志，只记录有证据价值、可支持后续判断或审计的内容。
- `log` 默认常驻并随任一单技能启用；用户明确关闭时才停用，且例外仅作用于当前任务。
- `logs/AGENTS.md` 是索引，日志正文是事实记录；不把两者合并成无结构长文。
- 时间戳默认按示例使用紧凑格式；带连字符格式通过 `--timestamp-style hyphen` 显式选择。
- 全文报告必须来自主 agent 已完成的真实报告，不能把内部推理或未经验证的草稿当成报告。
- 不记录隐藏系统提示、开发者提示、凭据、完整环境变量或其他敏感信息。
- 日志默认应适合 Git 提交；未经明确授权不暂存、提交、推送或创建标签。
- 日志写入后不重复调用本技能记录元日志；由 `logs/AGENTS.md` 和终端结果闭环。

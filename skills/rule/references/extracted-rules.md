# 从其他技能抽取的规则

本文件只记录可泛化到所有 agent 任务的治理规则，不复制专业流程。每行对应本目录一个现有技能。

| 来源技能 | 抽取的通用规则 | 在 `rule` 中的落点 |
|---|---|---|
| `all` | 迭代必须有收敛判据、轮数/时间守卫和失效模式识别 | 长任务 soft deadline、停滞阈值、终止后换方向 |
| `analy` | 结论必须有真实证据与可追溯来源 | 资源判断、异常判断和交付条件均要求本次证据 |
| `auto` | 无人值守仍需中断信号、停滞报告和自动收尾 | 后台任务可停止、可恢复、可审计 |
| `brainstorm` | 复杂任务先分类，隐藏复杂度只能升级不能降级 | 环境与任务分类；未知环境按共享处理 |
| `debug` | 无根因调查禁止修复；连续失败要质疑方案 | 进程异常后先取证，再 TERM/KILL，禁止盲目重跑 |
| `diff` | 先定范围，再检查冲突、未跟踪和二进制等边界 | 自动交付前逐文件范围审查 |
| `dispatch` | 只并行独立任务；派发失败有界重试并串行降级 | 子 agent 预算、并发限制、失败停止与回收 |
| `doctor` | 广域健康检查和入口/权限/语法边界先于修补 | 长任务启动前检查环境、资源和入口 |
| `fast` | 提速不能删除关键证据、安全性和质量闸门 | 节省资源不得降低精度、覆盖或验证 |
| `follow-up` | 状态与动作分离，阻塞和下一步可续接 | 进程与交付摘要明确当前状态和恢复点 |
| `form` | 目录职责、命名、大文件闸门和 Git 收尾可审计 | 自动提交前布局检查和 10 MB 硬闸门 |
| `go-on` | 孤儿进程先判类；可续任务不误杀，无用任务及时清理 | 停滞/中断处理和会话恢复 |
| `init` | 两阶段、幂等、先调查后写入 | 先建立预算和状态，再启动或交付；重跑不重复副作用 |
| `log` | 常驻、三态日志、证据压缩、大小上限和索引 | `rule` 与 `log` 同时常驻；阶段交付必须归档 |
| `make` | 最小改动、验证闭环、诚实与可追溯 | 预算最小充分，交付前验证，不虚报 |
| `md-tex-sync` | 渲染和构建闸门必须实测，构建应幂等可追踪 | 长任务输出、检查点和重复运行必须有可验证结果 |
| `optim` | 先测量后优化，主导项优先，正确性高于性能 | 资源异常先 profile，确认正确后再优化 |
| `phys-model` | 量纲、守恒、极限和边界是硬校验 | 大规模任务用规模/复杂度/误差预算证明资源需求 |
| `plan` | 任务是最小独立验证单元，计划必须自包含 | 进程预算和子 agent 指令包含完整停止条件 |
| `pure` | 穷尽候选、证据分级和双向映射 | 资源分类与环境/进程映射不得遗漏未知项 |
| `report` | 证据分级、完整叙事和行动导向 | 资源阻塞、验证缺口和下一步必须明确说明 |
| `research-notes` | 先记事实再下结论，保留过程证据 | 进度、异常、终止和交付判断保留可审计证据 |
| `review` | 早审查、问题分级、修复后回归 | 自动交付前做范围和风险审查，失败不提交 |
| `skill-creator` | 触发条件明确、规则形式匹配失败、分级披露 | `rule` 常驻触发与 SKILL/references 分层 |
| `tag` | 先看后打、历史链自检、禁止破坏性重写 | 条件式标签只做非破坏性创建和正常推送 |
| `tdd` | 生产改动先有失败测试，修复有回归证据 | 自动提交要求相关验证和回归通过 |
| `team` | worker 隔离、健康检查、单写者和失败重派 | 子 agent 并发上限、心跳、停滞检测和回收 |
| `test` | 声明闸门五步；本次输出先于完成声明 | 提交、推送和“进程正常”均要求本次证据 |
| `up` | 参考源与本地基线先刷新，变更后做联动验证 | 交付前刷新远程状态并检查索引/镜像一致性 |

## 统一后的规则优先级

1. 安全边界、正确性和用户明确约束优先；
2. 共享环境资源保护优先于局部速度；
3. 完整任务质量优先于节省资源；
4. 证据和可恢复性优先于自动推进；
5. 条件式自动交付优先于“等待用户再次确认”的默认 Git 流程，但不改变破坏性操作边界。

这些条目是跨技能共性的提炼，不覆盖 `debug` 的根因纪律、`test` 的验证方法、`tag` 的历史链规则或其他技能的
专业流程；执行时仍由对应技能负责领域细节。

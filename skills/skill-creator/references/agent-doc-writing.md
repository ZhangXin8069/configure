# Agent 文档写作检查表

本参考用于编写或修改 `SKILL.md`、`AGENTS.md`、技能引用文档以及任何由 agent 按需读取的说明。
目标不是把文字写短，而是让正确材料在正确分支、正确时机进入上下文。

## 1. 上下文指针

指针是当前上下文中对另一份材料的引用，例如技能 `description` 或 `AGENTS.md` 中的路径行。
指针同时承担两件事：

1. 说明目标材料是什么；
2. 列出应该读取它的不同分支。

检查：

- 触发词前置，不在句尾才出现；
- 每个独立分支只写一次，同义改写不重复占位；
- 正文已经明确表达的身份或用途不塞回指针；
- 必须读取的材料配强指针；指针仍不可靠时再考虑内联。

## 2. 两种负载

- 上下文负载：每轮都占用窗口和注意力的内容，例如常驻 `AGENTS.md` 行和技能描述。
- 认知负载：人需要记住“哪份文档何时使用”的成本。只把人的判断真正重要的选择留在这里。

按需读取的材料通过指针避免常驻窗口成本，但指针本身仍要付上下文成本。

## 3. 信息层级

按执行即时性放置内容：

1. 文件内步骤：agent 当前要按序执行的动作；
2. 文件内参考：执行中随时查阅的规则、定义和表格；
3. 披露参考：只有部分分支需要，放到 `references/` 并由指针触发。

每个概念的定义、规则和例外尽量放在同一标题下，避免同一含义散落多处。

## 4. 完成判据

每个步骤都要有可判断的完成条件，优先同时满足：

- 清晰：agent 能区分完成与未完成；
- 充分：判据要求穷尽必要工作，而不是只产出一个形式化列表。

模糊判据容易诱发提前结束；若判据无法量化，可拆成独立阶段或交接点，避免后续步骤过早暴露。

## 5. 引导词与正向表述

引导词是预训练模型中已有、能锚定一类行为的短概念，例如 `红/绿`、`tracer bullet`、`收紧循环`。
重复使用同一引导词，比每次解释整段理念更稳定。

优先写目标行为，而不是只写禁令。禁令会把被禁止的行为带入注意力；只有无法正向表达的安全护栏才使用禁止式，
并同时给出正确动作。

## 6. 修剪

- 一个含义只保留一个权威来源；
- 环境已能直接查询的事实不要缓存进文档，除非查询成本高或含隐含约定；
- 逐句检查相关性、时效性和“是否存在都不改变默认行为”；
- 删除无行为影响的说明，而不是只删几个字。

## 7. 提交前检查

- [ ] 描述只写触发分支，不泄露工作流 shortcut；
- [ ] 每份按需材料都有明确指针；
- [ ] 每个步骤有清晰、充分的完成判据；
- [ ] 同一含义只有一个权威位置；
- [ ] 长表或低频分支已移入 `references/`；
- [ ] 禁止式规则有正向替代动作；
- [ ] 文档中的命令、路径和工具在当前仓库可执行或明确标注依赖。

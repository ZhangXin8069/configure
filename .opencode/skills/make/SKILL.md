# make — 项目生成技能（聚合编排其他技能）

## TODO 管理（全局约定）

执行第一步用 **todowrite 工具**生成**详细 TODO 列表**：按任务分解为可独立验证的
子步骤、按依赖排序；**每完成一个子步骤立即调用 todowrite 更新状态**（进行中/完成）；
收尾时核对全部完成。约定全文见 `skills/AGENTS.md`「TODO 生成与实时更新约定」。

生成对象为**用户指定的项目**。本技能不重复发明流程，而是**编排调用**本目录下的全部技能
（init/tag/debug/optim/diff/analy/test），按"解析需求 → 调查规划 → 实现 → 测试 → 优化 →
复查 → 归档 → 打标"的全流程推进；其细节要求即本目录所有技能的汇总，执行时逐项落实。

## 核心原则（本目录所有技能要求汇总）

1. **先解析需求，不臆断**：生成对象、范围、约束、通过标准不明确时先提问（test/optim/debug 先问对问题）；
   所有问题在**第一次交互一次性全部提出**（编号列表），用户一次回答，不逐次追问。
2. **两阶段执行**：先只读调查产出计划表（阶段 A），确认后再统一执行写操作（阶段 B）
   （init 两阶段，避免边扫边改导致信息丢失）。
3. **先定范围后执行**：明确生成对象与比较范围，不臆断目标（diff 先定范围）。
4. **证据驱动**：一切结论与统计数字实测（debug/optim/diff/analy/test）；不编造文件、API、数据或收益。
5. **最小改动**：只改必要处，遵循代码库既有约定；修复与重构、优化与功能改动分离（debug/optim）。
6. **验证闭环**：生成后必须测试——失败按 debug 方法论循环修复，全部通过按 optim 方法论循环优化，
   每轮优化后回归全部测试（test）。
7. **不变量校验**：以量纲/守恒律/边界情形（空输入、0、越界、退化）校验结论（debug/test 复查）。
8. **幂等**：已生成/已归档内容不再重复处理；重复运行应输出"无变更"（init）。
9. **循环尝试直至成功**：一次失败不停止——基于新证据重新分析、优化方案后再执行，
   直至成功或用户终止；每次迭代更新日志（所有技能）。
10. **诚实与安全**：不确定就问；不越界访问；不代用户提交；触及系统配置前先说明（所有技能）。
11. **可追溯**：分析/报告类结论附 `文件:行号` 参考源（analy）。

## 会话日志

每次 make 会话必须在**当前工作目录（项目所在仓库根）**生成详细日志：

- 文件名格式：`.make.<时间戳>.log`（例如 `.make.2026-08-13-10-00-00.log`）
- 时间戳格式：`%Y-%m-%d-%H-%M-%S`：`TS=$(date +%Y-%m-%d-%H-%M-%S)`
- 日志**不入库**（与仓库 `.agent.*.log`、`.init.*.log`、`.tag.*.log`、`.debug.*.log`、
  `.optim.*.log`、`.diff.*.log`、`.analy.*.log`、`.test.*.log` 约定一致），全程**追加**写入（`>>`）
- 记录内容（**会话头**）：
  1. 开始时间、工作目录、git 分支与 HEAD（`git rev-parse --abbrev-ref HEAD`、`git log -1 --oneline`）、
     解析出的生成任务定义（对象/范围/约束/通过标准）；
- 记录内容（**过程**）：
  2. 调查结果（目录结构、既有约定、参考知识库）；生成计划表（拟新建/修改文件清单）；
  3. 用户确认结果；每个阶段关键命令与实际输出（`$ <命令>` + `exit=<退出码>`，
     输出过长截断并注明）；
  4. 测试计划与逐项结果；debug/optim 每次迭代（假设、改动 `文件:行号`、复测数据）；
  5. diff 复查统计；skill 归集/归档记录；tag 创建与推送结果；每次失败与重试；
- 记录内容（**会话尾**）：
  6. 最终汇总（结构化输出）；结束时间、总耗时；遗留项（未提交改动、待确认项）与下一步建议。

**记录规范**：关键事件以分隔行标记 `---- [YYYY-MM-DD HH:MM:SS] 事件描述 ----`；
命令统一记作 `$ <命令>` 并在结果行标注退出码；全程不覆盖、只追加。

## 历史日志预读（关键信息速览）

会话**第一步**只读预读本技能**最新一份**历史日志的**尾部汇总区**（只关注关键信息，不做深入解析）：

```bash
tail -20 "$(ls -1t .make.*.log 2>/dev/null | head -1)"   # 尾部汇总区：上次任务/结论/遗留项
```

- 关键信息：① 上次任务/对象；② 结论或收敛结果；③ 遗留项与下一步建议——其余（过程轮次、命令细节）一律跳过，不做深入 think
- 约束：只读不改；无历史日志（首次运行）时正常跳过，不视为错误；总耗时以秒级为限

### 前置上下文预读（工作目录说明文件与 agent 文件夹）

会话**第一步**与历史日志预读同步执行：只读当前工作目录的**说明文件**与 **agent 文件夹**
（清单可扩展，存在即读、缺失即跳过，不视为错误），只取关键信息、避免耗时过长：

```bash
# 1) 说明文件（按优先级取第一个存在的：AGENTS.md > README.md > CLAUDE.md > AGENT.md > CODEX.md）
for f in AGENTS.md README.md CLAUDE.md AGENT.md CODEX.md; do
  [ -f "$f" ] && { echo "== $f =="; head -40 "$f"; break; }
done
# 2) agent 文件夹（按优先级取第一个存在的：.opencode > .claude > .codex）
for d in .opencode .claude .codex; do
  [ -d "$d" ] || continue
  echo "== $d =="; ls "$d" | head -10
  [ -f "$d/AGENTS.md" ] && head -20 "$d/AGENTS.md"
  break
done
```

- 关键信息：项目约定/命令/目录结构/入口点/测试方式；agent 文件夹只列顶层结构（如 AGENTS.md、skills/）
- 约束：只读不改；文件/目录不存在时正常跳过；`head` 限行保证秒级耗时

### AGENTS.md 同步（必要时补充有益内容）

会话中如发现**当前工作目录的 AGENTS.md** 缺失本次任务相关且对后续会话有益的内容
（项目约定/命令/目录结构/入口点/测试方式/新功能说明），**必要时补充更新**，
保持约定文档与仓库状态同步：

- 只补充**确凿有益**的内容：本次任务确立的约定、验证过的命令、新入口点/结构变化；
  不写入个人化/临时性/未验证内容；
- **最小改动**：在既有章节内补充或新增小节，遵循原文档结构（表格/列表），不重写全文；
- **先读后写**：写入前先读 AGENTS.md 现状，避免重复条目与格式破坏；
- 补充位置与内容记入会话日志；改动不代提交（提示用户自行 git add/commit）。

## 工作流程

### Step 1. 解析生成对象（先问对问题）

收集并确认（缺项先提问，不臆断；**所有问题在第一次交互一次性全部提出**，用户一次回答，不逐次追问）：

| 信息项 | 说明 |
|---|---|
| 生成对象 | 用户指定的项目/脚本/配置/文档，名称与目标位置 |
| 项目类型 | 脚本（shell/python/...）、配置、文档（LaTeX/Markdown）、分析报告、完整项目 |
| 功能需求 | 期望行为、输入输出、边界情形 |
| 通过标准 | 如何判定"生成成功"（预期输出/数值容差/行为断言） |
| 约束 | 语言/工具链、设备（GPU/CPU）、精度、兼容范围、性能目标 |

输出一句**任务定义**（如"生成对象：bin/oopencode.sh（shell 启动器，实现日志与历史预读）"）
并记录到日志，避免歧义。

### Step 2. 环境与基线调查（阶段 A，只读，不改任何文件）

```bash
git rev-parse --is-inside-work-tree && git rev-parse --abbrev-ref HEAD && git log -1 --oneline
git status --short
find . -type f -not -path "./.git/*" -not -path "*/node_modules/*" \
  -not -path "*/__pycache__/*" -not -path "./tmp/*" | sort
```

1. **既有约定**：阅读仓库/目录的 `AGENTS.md`（确切命令、目录结构、入口点、框架怪癖、测试方式）；
   参考同目录既有代码的风格与命名（init 参考先于归档，analy 全库索引）。
2. **参考知识库**（analy 默认引入）：git 家目录下 `docs`/`books`/`refer` 等参考目录存在即
   建索引，主题相关时检索并入证据链；不存在则注明"未引入"。
3. **确认目标位置**：生成对象位置须在当前工作目录范围内；越界路径先向用户确认，不越界访问。
4. 调查结果记入会话日志（目录结构、约定要点、知识库覆盖）。

### Step 3. 规划与确认（dry-run 计划表）

- 输出**生成计划表**：拟新建/修改的文件清单（路径 + 内容要点）、调用的技能阶段、
  通过标准；默认 dry-run **不写任何文件**。
- 用户确认后进入阶段 B；用户明确"直接执行"/"apply" 时跳过确认（init 运行模式）。
- 计划表存入会话日志。

**计划表质量要求**（writing-plans 吸收）：
1. **任务粒度可独立验证**：每个计划任务是一个自含的完成单元——有自己的测试周期、
   可独立验证的交付物（"写失败测试→运行确认失败→实现→运行确认通过→提交"一步一动作）；
   配置/脚手架/文档类步骤并入其交付物所属任务，不单列空任务。
2. **无占位符**：禁止 "TBD"、"TODO"、"实现细节后补"、"类似任务 N"（代码必须写全，
   读者可能跳序阅读）；给出确切文件路径、接口签名、预期输出。
3. **覆盖检查**：计划完成后对照需求/规格逐条核对——每条需求都能指向一个任务；
   有需求无任务的补任务。
4. **一致性检查**：跨任务的函数名/接口签名/命名前后一致（Task 3 用 `clearLayers()`
   Task 7 用 `clearFullLayers()` 即计划 bug）。

### Step 4. 实现（阶段 B，最小改动）

1. 按计划逐文件生成/修改；遵循既有约定（命令、风格、目录结构、命名）；
2. 一次只专注当前任务，不擅自扩大范围；修复与重构分离；
3. 生成代码时的中间变量自行计算并保存（test 要求，可落盘 `test_out/intermediate/` 或项目产物目录）；
4. 语法/静态校验：shell 脚本 `bash -n <脚本>`；Python `python -m py_compile`；
   有 lint/typecheck 框架则必须运行（debug/test 验证闭环要求）；
5. 新增内容为 **agent 生成**（本技能产物即符合）→ 按 init 要求登记：
   完成后将生成此类内容的完整 skill 归集到本库根（git 家目录）`.opencode/skills/`；
6. 触及系统配置（PATH、rc 文件、全局配置）前先说明意图与回滚方式，经用户同意后执行。

### Step 5. 测试验证（调用 test 方法论）

1. **先定通过标准**：逐项预期输出/数值容差/行为断言，形成测试计划表写入日志；
2. 逐项执行：记录触发命令、实际输出（过长截断并注明）、退出码 `exit=N`，判定通过/失败/跳过；
3. 中间变量与最终结果、图表落盘 `test_out/`（`intermediate/`、`results/`、`figures/`），
   记录 dtype/设备标注；
4. **失败项** → 按 debug 方法论循环：复现→证据定位→二分收敛→不变量校验→最小修复→
   原复现路径回归→跑全部测试；每次迭代追加日志（`---- [...] 第 N 次 debug 迭代 ----`）；
5. 数值类项目注意设备切换（CUDA GPU 优先、CPU 回退、NPU 经确认）与多精度切换
   （默认 fp32，可 fp64/fp16），数据读写间显式管理精度转换（astype + 相对容差）。

### Step 6. 优化循环（调用 optim 方法论，可选）

全部测试通过后审视优化空间：

1. 测量基线（3–5 次取中位数，记录原始值序列）；复杂度/调用开销/IO/启动主导项分析；
2. 只优化主导项；最小改动；正确性优先（优化不得改变对外行为）；
3. 改动后**先回归全部测试**，再复测对比；收益量化如实记录，不虚报；
4. 循环直至目标达成、收益微小或用户终止；每次迭代追加日志。

### Step 7. 分析报告（调用 analy 方法论，可选）

用户要求或项目为分析/文档类时：

- 结论附参考源 `文件:行号`；代码片段用 `\lstinputlisting` 直引原文件（不转写）；
- LaTeX（中文用 ctex+xelatex）编译 PDF 到当前工作目录 `docs/`，
  命名 `analy_<slug>_<YYYYMMDD>.pdf`；编译失败读 `.log` 修复重编（循环至成功）。

### Step 8. 收尾（diff + init + tag）

1. **改动复查**（diff）：先概览（`git diff --stat` / `--numstat`）后详情（逐文件），
   边界校验：冲突标记（`git diff --check`）、调试残留、未跟踪文件（`git status` 中 `??`）、
   二进制/大文件、重命名（`git diff -M`）、权限位（`--summary`）；
2. **skill 归集**（init）：本技能生成的 agent 内容对应的完整 skill
   （即 make 技能自身或更专门的生成技能）复制归集到本库根 `.opencode/skills/<name>/`；
   更新相关 `AGENTS.md`（技能表登记）；
3. **版本标签**（tag，用户要求时）：先看后打——分析基线以来变更，构建诚实分组变更清单；
   注释标签消息格式 `follow <前一标签>, 1. 变更一; 2. 变更二; [opencode].`；
   先推分支后打标签、再推标签，默认同步远程；类型按上下文推断（无信号默认 dev）；
   破坏性操作（删除/改写已推送标签）先警告再执行；
4. **不代提交**：涉及 git 跟踪文件时提示用户自行 `git add` + 提交。

### Step 9. 总结（结构化输出）

```text
✓ make 完成
   任务:   <生成对象任务定义>
   改动:   <新建 N / 修改 M 文件，统计>
   测试:   <N 项通过 M 失败 K（跳过 S: 原因）>
   debug:  <N 次迭代>（修复: 文件:行号 <说明>，无则省略）
   optim:  <N 次迭代>（基线 → 优化后，收益量化，无则省略）
   产物:   <产物路径与格式，如 test_out/、docs/xxx.pdf>
   归档:   <skill 归集/AGENTS.md 更新记录，无则省略>
   标签:   <tag 创建与推送结果，无则省略>
   遗留:   <未提交改动/未覆盖项/待确认项，无则省略>
   日志:   .make.2026-08-13-10-00-00.log (debug 迭代 N, optim 迭代 M)
```

## 错误处理

| 场景 | 处理 |
|---|---|
| 生成对象不明确 | **一次性列出全部候选**（项目类型/位置/功能）提问确认，不逐次追问 |
| 目标位置越界（工作目录外） | 先向用户确认路径与访问权限，不越界访问 |
| 需求含糊（无通过标准） | **一次性列出全部候选**（预期行为/判定标准）提问确认 |
| 生成后测试失败 | 按 debug 循环（复现→定位→最小修复→回归），循环直至成功或用户终止 |
| 多次 debug 迭代仍失败 | 检查证据是否不足或方向错误；向用户报告进展与下一步，不无限循环 |
| 优化收益微小 | 报告权衡（复杂度 vs 收益），由用户决定取舍 |
| 无测试框架 | 纯 shell 至少 `bash -n` + 原复现路径手动回归 |
| 无 LaTeX 工具链（需报告） | 报告缺项并提供安装建议，不静默跳过 |
| 生成内容为 agent 产出 | 按 init 要求归集完整 skill 到本库根 `.opencode/skills/` |
| 打标签失败/推送失败 | 按 tag 技能定位重试（循环），重试仍失败暂停并报告 |
| 计划未确认即要求执行 | dry-run 默认不写文件；执行前展示计划表并获确认（除非明确 "apply"） |
| 幂等性校验 | 重复运行同一生成任务应输出"无变更"或明确跳过已处理项 |

## 注意事项

- 生成全程遵循本目录所有技能的公共约定：时间戳 `TS=$(date +%Y-%m-%d-%H-%M-%S)`、
  会话日志不入库且全程追加、关键事件分隔行标记、命令记 `$ <命令>` + `exit=<退出码>`；
- 以实测为准，不虚报通过/失败与收益；不编造文件、API、行号与数据；
- 不提交代码、不删除文件（用户未明确要求时）；涉及 git 跟踪文件时提示用户自行提交；
- 不越界访问工作目录之外的内容；触及系统配置前先说明意图与回滚方式；
- 会话日志 `.make.<时间戳>.log` 与产物不入库，由用户决定保留或清理。
